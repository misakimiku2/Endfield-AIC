# 汇流器（Converger）简化重构 - Product Requirement Document

## Overview
- **Summary**: 彻底简化汇流器的实现逻辑，移除复杂的缓冲槽位（convergerBuffer）和 skipAdvanceOnce 机制，让汇流器表现得像一个"智能转角传送带"——3条输入带按先到先得（FCFS）原则，将物品平滑、自然地汇流到1条输出带，处理速度与传送带一致（0.5单位/秒，即2秒/格）。
- **Purpose**: 修复当前汇流器连接传送带时出现的各种动画bug（输入端物品变箭头、输出端物品分批次移动/卡顿、物品队列异常），这些问题的根源是初始实现过度复杂化：引入了不必要的内部缓冲、skipAdvanceOnce延迟标记、以及特殊的传送带推进顺序，导致物品流动不自然。
- **Target Users**: 游戏内工厂建造玩家，期望物流设备行为直观可预测、动画平滑无卡顿。

## Goals
- 汇流器内同一时间只有一个物品在穿越（单通道）
- 物品从输入带到输出带的过渡平滑自然，像转角传送带一样无停顿、无闪烁、无箭头突变
- 3个输入方向严格遵循先到先得（FCFS）原则
- 输出传送带物品队列紧密排列、连续移动，无分批次卡顿现象
- 输入传送带在汇流器忙碌时自然堵塞（变红），物品在带面上排队等待
- 移除所有导致动画bug的复杂机制（skipAdvanceOnce、convergerBuffer、特殊推进顺序）
- 代码简洁，与分流器（Splitter）的简洁实现风格保持一致

## Non-Goals (Out of Scope)
- 不改变汇流器的端口定义（3输入：左/上/右；1输出：下）
- 不改变汇流器的处理速度（0.5单位/秒）
- 不改变汇流器的UI面板和弹窗
- 不改变传送带的基础渲染和动画系统
- 不改变分流器（Splitter）的现有正确行为
- 不添加物品优先级等额外功能（严格FCFS）

## Background & Context
### 当前实现的问题分析
当前汇流器实现存在以下过度设计的问题：
1. **convergerBuffer 缓冲槽位**: 试图在汇流器内部存储1个物品，增加了状态复杂度，导致物品需要"先进入缓冲→再推送到输出带"两步走，破坏了动画连续性
2. **skipAdvanceOnce 标记**: 推送物品到输出带后让物品在position 0（建筑遮挡格）额外停留一个tick，导致物品出现"先变箭头→再变图片"的视觉问题，以及紧密排列时分批次移动
3. **isInputToConverger 特殊推进顺序**: 对汇流器输入带采用"先消费再推进"的特殊顺序，与其他设备（先推进再消费）不一致，导致物品位置计算异常
4. **_drainConvergerBuffer 单独排空逻辑**: 缓冲槽位需要额外的排空逻辑，增加了时序复杂度
5. **convergerArrivalTimestamps 过于复杂**: 虽然FCFS方向是对的，但与缓冲机制耦合在一起，增加了bug风险

### 用户期望的行为模型
用户用非常直观的方式描述了期望行为：
> "当左边输入端传送带的物品1进入到汇流器后，其实运行速度是跟'创建了一格→↓方向的转角传送带'是一样的，只需要把这个物品正常的像转角传送带一样自然的推到下方的输出端即可，并且在这个过程中，其他上、右的传送带就把汇流器这一格当作堵塞，等到物品1走出汇流器这一格之后，左边传送带就会收到堵塞的信号，上方的传送带的堵塞信号消失，上方传送带就会自然的把物品2推入到汇流器往下移动。"

核心模型：**汇流器 = 单通道虚拟转角**。它不是一个有内部存储的"设备"，而是一个让3条输入带轮流通过的"交通指挥"，物品通过它的速度和在普通传送带上完全一致。

### 与分流器的对比
分流器（1进3出）在修复后工作正常，它的实现特点：
- 有1个物品的缓冲（但这是为了处理输出带暂时满的情况）
- 不使用skipAdvanceOnce（或已修复其导致的问题）
- 物品直接从输入带推送到输出带

汇流器应该反向采用同样简洁的模式。

## Functional Requirements
- **FR-1**: 汇流器同一时间只允许一个物品穿越。当有物品正在穿越时，所有其他输入传送带视为堵塞状态（末端停止前进、显示红色堵塞指示）。
- **FR-2**: 物品从选中的输入带直接推送到输出带，不经过内部缓冲，推送过程不使用skipAdvanceOnce。
- **FR-3**: 输入方向选择严格遵循FCFS（先到先得）：哪个输入方向的物品先到达传送带末端（可被汇流器处理），就优先处理哪个方向。
- **FR-4**: 物品在输出带上的移动速度与普通传送带完全一致（0.5单位/秒），紧密排列的物品连续移动，无分批次卡顿。
- **FR-5**: 输入带上的物品在汇流器忙碌时，自然排队到传送带末端，到达末端后停止前进（传送带堵塞）。
- **FR-6**: 当输出带满（无法接收新物品）时，汇流器保持忙碌/堵塞状态，输入带上的物品继续排队等待。
- **FR-7**: 汇流器输入带的tick处理顺序与其他设备一致（先推进再消费），移除isInputToConverger特殊分支。
- **FR-8**: 移除convergerBuffer（缓冲槽位）机制以及相关的_drainConvergerBuffer排空逻辑。
- **FR-9**: 移除汇流器相关的skipAdvanceOnce使用。
- **FR-10**: 简化FCFS实现，不再与缓冲机制耦合，只跟踪"哪个方向先有物品ready"。

## Non-Functional Requirements
- **NFR-1**: 代码简洁性：汇流器相关逻辑代码量减少50%以上，移除所有不必要的状态和分支。
- **NFR-2**: 动画平滑性：物品从输入带到输出带的过渡无视觉跳跃、无箭头闪烁、无分批次移动，人眼观察为连续平滑运动。
- **NFR-3**: 行为一致性：汇流器输入/输出传送带的物品移动行为与普通传送带/转角传送带一致，无特殊时序。
- **NFR-4**: 可维护性：汇流器逻辑集中，与分流器逻辑结构对称，易于理解和后续修改。

## Constraints
- **Technical**: Flutter/Dart项目，使用现有的ConveyorBelt物品段（itemSegments）模型和基于0.5Hz tick的仿真引擎，不能重写整个传送带系统。
- **Business**: 必须在现有项目架构内修改，不能破坏其他设备（分流器、物流桥、仓库设备、冶炼炉等）的正常工作。
- **Dependencies**: 依赖现有的传送带pushSourceItem/canAcceptNewItemFromStart/advanceItemSegments机制。

## Assumptions
- 输出传送带的canAcceptNewItemFromStart能够正确反映"输出带起始端是否有空间接收新物品"，这可以作为汇流器是否"忙碌"的判断依据。
- 同一tick内传送带按顺序处理时，先处理的输入带推送物品到输出带后，输出带状态更新，后续输入带的canAccept检查会正确返回false。
- 简化后的FCFS机制（仅记录最早到达方向，不与缓冲耦合）足以保证先到先得顺序。
- 移除skipAdvanceOnce后，物品不会出现瞬移问题（之前的瞬移问题已通过其他修复解决，如freezeProgress渐进式解冻）。

## Acceptance Criteria

### AC-1: 单物品穿越，其他输入堵塞
- **Given**: 汇流器连接了3条输入传送带（左、上、右），每条输入带上都有物品正向汇流器移动
- **When**: 左侧输入带的物品首先到达汇流器入口
- **Then**: 左侧物品开始进入汇流器并向输出带移动；上、右两条输入带在汇流器入口处堵塞（物品停在末端，传送带显示红色堵塞）
- **Verification**: `human-judgment`
- **Notes**: 通过视觉观察验证

### AC-2: 物品平滑穿越无卡顿
- **Given**: 单个物品从左侧输入带进入汇流器
- **When**: 物品从输入带末端移动到输出带并继续前进
- **Then**: 物品动画平滑连续，没有短暂变成箭头的现象，没有停顿或跳跃，移动速度与传送带一致（2秒走过1格）
- **Verification**: `human-judgment`

### AC-3: FCFS顺序执行
- **Given**: 3条输入带都有物品到达汇流器入口，到达顺序为：左→上→右
- **When**: 汇流器依次处理物品
- **Then**: 物品处理顺序严格为左→上→右，每个物品完全离开汇流器区域后才开始处理下一个
- **Verification**: `human-judgment`

### AC-4: 输出带物品紧密排列无分批
- **Given**: 汇流器输出带连接到一个死胡同（或慢速消耗设备），多个物品连续通过汇流器进入输出带
- **When**: 物品在输出带上排队移动
- **Then**: 物品在输出带上紧密排列、连续向前移动，不会出现"第一个前进→后面3个停下→第一个走远后后面突然刷新跟上"的分批次现象
- **Verification**: `human-judgment`

### AC-5: 输出带满时堵塞输入
- **Given**: 汇流器输出带已被物品填满（末端堵塞或设备已满）
- **When**: 输入带物品试图进入汇流器
- **Then**: 汇流器保持堵塞状态，所有输入带物品在入口处排队等待，直到输出带有空间
- **Verification**: `human-judgment`

### AC-6: 输入带物品自然排队
- **Given**: 汇流器正在处理一个物品，某条输入带上有连续多个物品
- **When**: 物品向汇流器移动
- **Then**: 物品在输入带上自然紧密排队，到达汇流器入口（末端）后停下等待，不会消失或异常
- **Verification**: `human-judgment`

### AC-7: 代码简化验证
- **Given**: 重构完成后的代码
- **When**: 检查belt_simulation_logic.dart和project.dart中汇流器相关代码
- **Then**: convergerBuffer相关字段和方法已移除；skipAdvanceOnce在汇流器逻辑中不再使用；isInputToConverger特殊分支已移除；汇流器逻辑代码行数显著减少
- **Verification**: `programmatic`

### AC-8: 不破坏分流器和其他设备
- **Given**: 重构完成后
- **When**: 测试分流器、物流桥、冶炼炉等其他物流/生产设备
- **Then**: 分流器物品分流动画正常，其他设备行为与重构前一致，无回归bug
- **Verification**: `human-judgment`

## Open Questions
