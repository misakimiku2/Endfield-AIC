# 设备弹窗物品栏滚动性能优化

## 问题分析

用户反馈：设备弹窗的物品栏在物品种类较多时（特别是"产物"栏）上下滚动明显卡顿。

### 根本原因（按严重程度排序）

1. **100ms 全量 setState 定时器**（`building_detail_dialog.dart:118-120`）
   - 每 100ms 调用 `setState(() {})`，导致整个弹窗 widget 树每秒重建 10 次
   - GridView 及其所有可见格子被反复重建

2. **`_filteredItems` getter 每次 build 重新计算**（`building_detail_dialog.dart:187-190`）
   - 由于定时器，每秒被调用约 20 次，每次遍历全部 `_allItems` 并创建新 List

3. **每个格子的 SVG 字符串在每次 build 重新生成与解析**（`building_resource_panel.dart:107-110`）
   - `gridTileSvg()` 每次都拼接字符串，`SvgPicture.string()` 每次都重新解析
   - 产物栏格子多，重建成本叠加，卡顿明显

4. **全程没有 RepaintBoundary**
   - 定时器引发的重绘波及整个弹窗图层，无法隔离

5. **滚动驱动用 `animateTo(150ms)`**（`building_detail_dialog.dart:621-625`）
   - 快速连续滚动时，多个 150ms 动画相互打断，导致抖动/不跟手

## 优化方案

本次采用**无副作用的纯性能优化**，不改变任何现有UI行为和视觉表现。100ms 定时器的彻底重构（改用局部 ValueNotifier 刷新进度）风险较高，留作后续优化，本次通过缓存和隔离来降低其影响。

### 改动 1：缓存 `_filteredItems`

**文件**：`lib/widgets/building_detail_dialog.dart`

**当前**（L187-190）：
```dart
List<ResourceItem> get _filteredItems {
  final tabCategory = _tabLabels[_resourceTabIndex];
  return _allItems.where((item) => item.category == tabCategory).toList();
}
```

**改为**：
- 新增字段 `List<ResourceItem> _cachedFilteredItems = [];`
- 在 `initState` 中（`_allItems` 赋值后）调用 `_refreshFilteredItems()` 初始化
- 新增方法 `_refreshFilteredItems()`，按当前 `_resourceTabIndex` 过滤并存入字段
- 在标签切换的 `onTap`（L551 附近 `setState(() => _resourceTabIndex = index)`）中，先调用 `_refreshFilteredItems()` 再 setState
- `_buildGridArea` 中的 `_filteredItems` 引用全部改为 `_cachedFilteredItems`

**效果**：消除每秒 20 次的重复过滤计算。

### 改动 2：缓存 `ResourceGridTile` 的 SvgPicture 对象

**文件**：`lib/widgets/building_resource_panel.dart`

**当前**（L107-110）：每次 build 调用 `gridTileSvg()` 生成字符串并创建新的 `SvgPicture.string()`。

**改为**：
- 在 `ResourceGridTileState` 中新增两个字段：
  ```dart
  late final SvgPicture _normalBg;
  late final SvgPicture _hoveredBg;
  ```
- 在 `initState` 中预生成两个 SvgPicture 实例：
  ```dart
  _normalBg = SvgPicture.string(
    gridTileSvg(widget.item.level, isHovered: false),
    fit: BoxFit.fill,
  );
  _hoveredBg = SvgPicture.string(
    gridTileSvg(widget.item.level, isHovered: true),
    fit: BoxFit.fill,
  );
  ```
- build 方法中改为引用缓存对象：`_hovering ? _hoveredBg : _normalBg`

**效果**：SVG 字符串生成和解析只在格子创建时执行一次，后续 build 零成本引用。`SvgPicture` 是同一实例，flutter_svg 不会重新解析。

### 改动 3：添加 RepaintBoundary 隔离重绘

**文件**：`lib/widgets/building_detail_dialog.dart`

- 在 `_buildGridArea` 的 `GridView.builder` 外层包裹 `RepaintBoundary`
- 在 `itemBuilder` 返回的 `ResourceGridTile` 外层包裹 `RepaintBoundary`

**文件**：`lib/widgets/building_resource_panel.dart`
- 无需改动（RepaintBoundary 加在父级 itemBuilder 中）

**效果**：
- GridView 整体作为一个独立图层，100ms 定时器触发的右侧面板重绘不会波及物品栏
- 每个格子独立图层，单个格子悬停动画不会触发兄弟格子重绘

### 改动 4：优化滚动驱动，改用 jumpTo

**文件**：`lib/widgets/building_detail_dialog.dart`

**当前**（L615-628）：滚轮事件用 `animateTo(150ms, easeOutCubic)`，快速滚动时多个动画相互打断。

**改为**：
```dart
_gridScrollController.jumpTo(target);
```

**效果**：滚动立即响应，无动画堆叠，跟手不抖动。保留 `_onGridScrolled()` 调用以维持滚动条显隐逻辑。

## 不做的事项（及原因）

- **不移除 100ms 定时器**：它服务于生产进度、库存数量等动态UI的刷新。彻底移除需要将所有依赖它的UI改为 ValueNotifier/AnimatedBuilder 局部刷新，改动面大、风险高。本次通过改动 2（缓存SVG）和改动 3（RepaintBoundary）已能大幅降低定时器对物品栏的影响。
- **不改变 GridView 的懒加载结构**：已经是 `GridView.builder`，结构正确。
- **不改变物品图片的加载方式**：`Image.asset` 已使用 `cacheWidth`/`cacheHeight`，是良好实践。

## 验证步骤

1. `flutter analyze` 确认无编译错误
2. 打开设备弹窗，切换到"产物"栏，快速上下滚动，确认卡顿明显改善
3. 确认滚轮滚动跟手无抖动
4. 确认格子悬停效果（SVG变色、图片放大、tooltip）正常
5. 确认标签切换正常，滑块动画正常
6. 确认取货口添加物品模式下的方形添加按钮和悬停效果正常
7. 确认右侧合成面板的生产进度刷新正常（100ms定时器仍保留）
