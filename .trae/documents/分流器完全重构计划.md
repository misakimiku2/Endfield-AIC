# 分流器完全重构计划

## 概述

完全重构分流器（splitter_1x1）的物品传输逻辑，使其从"存储式设备"变为"网关式设备"，参照物流桥（belt_bridge）的方向通道机制，实现：
1. 不存储物品 —— 物品流入后立即被分配到对应输出传送带，至多保留 1 个滞留物品
2. 循环分配 —— 每次有物品进入时，按 **左→上→右** 顺序循环分配，而非填满左侧再走上
3. 处理速度 0.5 单位/秒 —— 与传送带速度一致，物品进入后需 2 秒处理（一个动画周期）才可被输出带拉取

## 当前状态分析

### 核心问题

| 问题 | 当前实现 | 期望行为 |
|---|---|---|
| 分流器可存储 50 个物品 | 使用 `inputItemId`/`inputItemCount`（容量 `maxInputItemCount = 50`） | 至多 1 个滞留物品 |
| 所有输出带共享同一缓冲区 | `_getAvailableOutputItemIdForBeltStart` 返回 `pb.inputItemId`，3 条输出带竞争 | 按方向独立分配 |
| 填满左侧再走其他 | 先 tick 的输出带先拿走物品 | 严格循环 左→上→右 |
| 1x1 建筑端口无法区分方向 | `_findOutputPortIndexAtCell` 对 1x1 建筑总返回 0 | 用传送带出口方向匹配 |
| Isolate 覆盖主线程状态 | `_applyTickResult` 覆盖 `inputItemId`/`inputItemCount`/`outputItems` | 跳过物流设备 |
| 无处理速度限制 | 物品进入后立即可被拉取 | 0.5 单位/秒（2 秒处理时间） |

### 时序机制参考

传送带动画由 `_beltArrowController`（`AnimationController`，`duration: 2 seconds`，`..repeat()`）驱动：
- 每个 2 秒周期 = 1 格传输 = 0.5 单位/秒
- `_onBeltAnimationFrame(globalProgress)` 在每帧调用，`globalProgress` 在 0→1 间循环
- 传送带 tick（物品推进）在 `previous > 0.5 && progress < 0.5` 时触发（每周期一次）

分流器应使用相同的 `globalProgress` 增量来推进处理进度，确保与传送带速度一致。

### 1. project.dart — PlacedBuilding 添加分流器机制

**位置**: `lib/models/project.dart`，在物流桥方法块（第 219-289 行）之后添加。

#### 1.1 添加常量与字段

```dart
static const String _splitterId = 'splitter_1x1';
static const String _splitterSlotPrefix = '__splitter_slot__';
static const int maxSplitterSlotCount = 1; // 至多1个滞留物品

// 分流器轮询索引：0=left, 1=up, 2=right
int splitterCycleIndex = 0;

// 分流器槽位处理进度：0.0=刚进入，1.0=处理完成可被拉取
// 0.5单位/秒 => 2秒填满 => 与传送带速度一致
double splitterSlotFillProgress = 0.0;
```

#### 1.2 添加 getter 与槽位存取方法

```dart
bool get isSplitter => building.id == _splitterId;

/// 分流器单槽位的键格式：__splitter_slot__<direction>__<itemId>
String _splitterSlotKey(String assignedDirection, String itemId) =>
    '$_splitterSlotPrefix$assignedDirection__$itemId';

/// 获取槽位中物品的分配方向（left/up/right），无物品返回 null
String? splitterSlotAssignedDirection() {
  if (!isSplitter) return null;
  for (final entry in outputItems.entries) {
    if (entry.key.startsWith(_splitterSlotPrefix) && entry.value > 0) {
      final rest = entry.key.substring(_splitterSlotPrefix.length);
      return rest.split('__').first;
    }
  }
  return null;
}

/// 获取槽位中物品的 ID，无物品返回 null
String? splitterSlotItemId() {
  if (!isSplitter) return null;
  for (final entry in outputItems.entries) {
    if (entry.key.startsWith(_splitterSlotPrefix) && entry.value > 0) {
      final rest = entry.key.substring(_splitterSlotPrefix.length);
      final parts = rest.split('__');
      return parts.length >= 2 ? parts.last : null;
    }
  }
  return null;
}

bool get splitterSlotOccupied => splitterSlotItemId() != null;

/// 槽位中物品是否已处理完成（可被输出带拉取）
bool get splitterSlotReady => splitterSlotOccupied && splitterSlotFillProgress >= 1.0;

/// 判断是否可接收物品：仅当槽位为空时
bool canAcceptSplitterInputItem(String itemId) {
  if (!isSplitter || itemId.isEmpty) return false;
  return !splitterSlotOccupied;
}

/// 接收物品进入槽位，并分配到下一个循环方向（左→上→右）
/// 重置处理进度为 0，需 2 秒（0.5单位/秒）处理完成
bool acceptSplitterInputItem(String itemId) {
  if (!canAcceptSplitterInputItem(itemId)) return false;
  const cycleOrder = ['left', 'up', 'right'];
  final direction = cycleOrder[splitterCycleIndex % 3];
  splitterCycleIndex = (splitterCycleIndex + 1) % 3;
  final key = _splitterSlotKey(direction, itemId);
  outputItems[key] = 1;
  splitterSlotFillProgress = 0.0; // 重置处理进度
  return true;
}

/// 推进槽位处理进度（由 canvas_editor 在每帧调用）
/// delta 来自 _beltArrowController 的 globalProgress 增量
/// 2秒周期 => delta 总和 1.0 = 处理完成
void advanceSplitterSlotProgress(double delta) {
  if (!isSplitter || !splitterSlotOccupied) return;
  if (splitterSlotFillProgress >= 1.0) return;
  splitterSlotFillProgress = (splitterSlotFillProgress + delta).clamp(0.0, 1.0);
}

/// 查询指定输出方向上是否有可提供的物品
/// 仅当槽位物品已处理完成 且 分配方向与请求方向匹配时返回物品 ID
String? splitterItemIdForOutputDirection(String outputDirection) {
  if (!isSplitter || !splitterSlotReady) return null;
  final slotDirection = splitterSlotAssignedDirection();
  if (slotDirection == null || slotDirection != outputDirection) return null;
  return splitterSlotItemId();
}

/// 消费指定输出方向上的物品
bool consumeSplitterOutputItem(String itemId, String outputDirection) {
  if (!isSplitter || itemId.isEmpty || !splitterSlotReady) return false;
  final slotDirection = splitterSlotAssignedDirection();
  if (slotDirection != outputDirection) return false;
  final slotItemId = splitterSlotItemId();
  if (slotItemId != itemId) return false;
  final key = _splitterSlotKey(outputDirection, itemId);
  outputItems.remove(key);
  splitterSlotFillProgress = 0.0; // 重置进度，为下一个物品准备
  return true;
}
```

**设计要点**:
- 单槽位容量 1 —— 满足"至多 1 个滞留物品"
- 物品进入时立即分配方向并推进轮询索引 —— 实现严格循环
- 处理进度 0→1.0 对应 2 秒（0.5 单位/秒）—— 与传送带速度一致
- 输出带仅在 `splitterSlotReady`（进度≥1.0）时才可拉取 —— 确保处理时间
- 复用 `outputItems` Map 存储槽位（带前缀键），与物流桥模式一致

#### 2.2 `_onBeltAnimationFrame` 添加分流器进度推进（第 391 行）

在方法开头（计算 belt tick 之前）添加分流器进度推进：

```dart
void _onBeltAnimationFrame(double globalProgress) {
  // 计算本帧 globalProgress 增量（处理 0→1 循环回绕）
  double progressDelta = globalProgress - _prevGlobalProgress;
  if (progressDelta < 0) progressDelta += 1.0;
  _prevGlobalProgress = globalProgress;

  // 推进所有分流器的槽位处理进度（0.5单位/秒，2秒周期）
  if (progressDelta > 0) {
    for (final pb in _project.buildings) {
      if (pb.isSplitter) {
        pb.advanceSplitterSlotProgress(progressDelta);
      }
    }
  }

  final activeIds = _project.conveyors.map((belt) => belt.id).toSet();
  // ... 原有逻辑不变
}
```

**原理**: `_beltArrowController` 以 2 秒为周期 repeat，`globalProgress` 在 0→1 间循环。每帧的 `progressDelta` 之和在 2 秒内为 1.0，对应 0.5 单位/秒。

#### 2.4 `_transferBeltOutputToBuilding`（第 539-566 行）

在 `isBeltBridge` 分支之后添加分流器分支：

```dart
bool _transferBeltOutputToBuilding(
    ConveyorBelt belt, PlacedBuilding building) {
  if (building.building.maxInputs <= 0) return false;
  final itemId = belt.outputReadyItemId();
  if (itemId == null) return false;
  if (building.isBeltBridge) {
    final outputDirection = _beltArrivalDirection(belt);
    if (outputDirection == null) return false;
    if (!building.acceptBridgeInputItem(itemId, outputDirection)) {
      return false;
    }
    belt.removeOutputReadyItem();
    return true;
  }
  // 分流器：接收物品并分配到下一个循环方向，重置处理进度
  if (building.isSplitter) {
    if (!building.acceptSplitterInputItem(itemId)) return false;
    belt.removeOutputReadyItem();
    return true;
  }
  // 仓库存货口...
  if (building.building.id == DepotLoaderConfig.id) {
    _project.incrementWarehouseItem(itemId);
    belt.removeOutputReadyItem();
    return true;
  }
  if (!building.acceptInputItem(itemId)) return false;
  if (building.activeRecipeId == null) {
    _autoSelectRecipe(building, itemId);
  }
  belt.removeOutputReadyItem();
  return true;
}
```

#### 2.5 `_getAvailableOutputItemIdForBeltStart`（第 593-630 行）

```dart
String? _getAvailableOutputItemIdForBeltStart(ConveyorBelt belt) {
  if (belt.path.isEmpty) return null;
  final start = belt.path.first;
  for (final pb in _project.buildings) {
    final outputIndex = _findOutputPortIndexAtCell(pb, start);
    if (outputIndex == null) continue;

    if (pb.isBeltBridge) {
      final outputDirection = _beltExitDirection(belt);
      return outputDirection == null
          ? null
          : pb.bridgeItemIdForOutputDirection(outputDirection);
    }

    // 分流器：按传送带出口方向匹配槽位中物品的分配方向
    // 仅当槽位物品处理完成（splitterSlotReady）时才提供
    if (pb.isSplitter) {
      final outputDirection = _beltExitDirection(belt);
      return outputDirection == null
          ? null
          : pb.splitterItemIdForOutputDirection(outputDirection);
    }

    // 其他物流设备（汇流器、物品控制口）：保持原有存储逻辑
    if (LogisticsUnitRenderer.isLogisticsUnit(pb.building.id)) {
      return pb.inputItemCount > 0 ? pb.inputItemId : null;
    }
    // ... 仓库取货口、配方设备（不变）
  }
  return null;
}
```

### 3. simulation_engine.dart — 跳过物流设备状态覆盖

**位置**: `lib/canvas/simulation_engine.dart`，`_applyTickResult` 方法（第 97-113 行）。

**问题**: Isolate 不处理物流设备（无配方会跳过），但 `_applyTickResult` 仍会用 Isolate 返回的陈旧数据覆盖主线程的 `inputItemId`/`inputItemCount`/`outputItems`，导致分流器槽位状态和物流桥通道状态被重置。

**修改**: 在循环开头跳过物流桥和分流器：

```dart
void _applyTickResult(SimTickResult result) {
  if (_project == null) return;

  for (final br in result.buildings) {
    final pb = _project!.buildings.where((b) => b.id == br.id).firstOrNull;
    if (pb != null) {
      // 物流设备状态由 canvas_editor 主线程管理，跳过 Isolate 覆盖
      if (pb.isBeltBridge || pb.isSplitter) continue;

      pb.isBlocked = br.isBlocked;
      pb.productionProgress = br.productionProgress;
      pb.inputItemId = br.inputItemId.isEmpty ? null : br.inputItemId;
      pb.inputItemCount = br.inputItemCount;
      if (br.activeRecipeId != null) {
        pb.activeRecipeId = br.activeRecipeId;
      }
      pb.outputItems = Map<String, int>.from(br.outputItems);
    }
  }
  // ... 传送带部分不变
}
```

## 物品流（重构后）

```
输入带 → _transferBeltOutputToBuilding
  → acceptSplitterInputItem(itemId)
    → 槽位为空？分配方向 cycleOrder[cycleIndex]，推进索引
    → splitterSlotFillProgress = 0.0（开始处理）
    → 存入 outputItems
    → 槽位已满？拒绝（反压传播到输入带）

每帧 → advanceSplitterSlotProgress(delta)
  → splitterSlotFillProgress += delta（2秒累计到1.0）

输出带(左) tick → _getAvailableOutputItemIdForBeltStart
  → splitterItemIdForOutputDirection('left')
  → splitterSlotReady（进度≥1.0）且方向匹配？返回 itemId : null
  → _consumeOutputItemForBeltStart → consumeSplitterOutputItem → 清空槽位，重置进度
```

**时序示例**（3 条输出带均可用）:
- t=0s: 物品1进入 → 分配'left'，进度=0
- t=0~2s: 进度 0→1.0（每帧推进）
- t=2s: 进度≥1.0，左侧带 tick → 拉走物品1 → 槽位空，进度重置
- t=2s: 物品2进入 → 分配'up'，进度=0
- t=2~4s: 进度 0→1.0
- t=4s: 上方带 tick → 拉走物品2 → 槽位空
- t=4s: 物品3进入 → 分配'right'，进度=0
- ...
- 吞吐率：1物品/2秒 = 0.5单位/秒 ✓

**反压示例**（左侧带满）:
- t=0s: 物品1进入 → 分配'left'，进度=0
- t=2s: 进度≥1.0，但左侧带满无法拉走 → 槽位被占用
- t=2s: 物品2进入 → 槽位已满 → 拒绝（输入带反压）
- t=4s: 左侧带腾出空间 → 拉走物品1 → 槽位空，进度重置
- t=4s: 物品2进入 → 分配'up'，进度=0

## 假设与决策

1. **不修改 converger（汇流器）和 item_control_port（物品控制口）** —— 它们继续使用原有 `inputItemId`/`inputItemCount` 存储逻辑，仅分流器改为网关模式。
2. **不修改 transport_belt.dart** —— 当前传送带创建逻辑不涉及分流器专用代码，端口匹配通过 `_beltExitDirection` 在 canvas_editor 中解决。
3. **不修改 buildings_db.json** —— 端口定义（下输入、左/上/右输出）已正确，无需调整。
4. **`splitterCycleIndex` 和 `splitterSlotFillProgress` 不需要序列化** —— PlacedBuilding 当前无 toJson/fromJson 方法，新增字段无需额外处理。
5. **物流桥的 Isolate 覆盖问题一并修复** —— `_applyTickResult` 跳过 `isBeltBridge`，防止物流桥通道状态被覆盖（潜在 bug 顺带修复）。
6. **轮询顺序固定为 left→up→right** —— 与分流器端口定义顺序（up=0, left=1, right=2）不同，使用独立的 `cycleOrder` 常量确保顺序正确。
7. **处理进度基于 `_beltArrowController` 的 `globalProgress` 增量** —— 该控制器以 2 秒为周期 repeat，增量总和 1.0 = 2 秒 = 0.5 单位/秒，与传送带速度完全一致。
8. **处理进度在每帧推进（非每 tick）** —— 确保进度连续平滑，物品在 2 秒后立即可用（无需等待下一个 tick 对齐）。
