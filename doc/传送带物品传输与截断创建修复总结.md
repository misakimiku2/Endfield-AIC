# 传送带物品传输与截断创建修复总结

## 背景

本次修改围绕传送带物品队列、生产设备输入端口接收、输入阻塞后的动画停止，以及在已有物品的传送带上截断创建新传送带时的物品继承问题展开。

原始问题主要表现为：

- 后续物品到达前方停止队列后会消失，并继续播放循环传输动画。
- 传送带连接生产设备输入端口后，设备库存增加，但传送带上的物品动画仍然不断循环。
- 当设备输入满或输入物品类型不一致时，物品应停在设备输入口前一格，但实际存在跳位或继续循环动画。
- 在有物品的旧传送带上截断创建新传送带时，新传送带物品丢失，或继承旧的停止帧导致动画不自然。

## 核心设计

### 1. 多物品队列模型

在 `ConveyorBelt` 中引入并强化 `ConveyorItemSegment` 队列段模型。

每个物品段记录：

- `itemId`：物品类型。
- `fillCount`：该物品段已经填充到的路径索引。
- `drainCount`：该物品段已经排空到的路径索引。
- `freezeProgress`：物品停止动画使用的冻结进度。

这样一条传送带可以同时表达多个物品队列，例如前方是物品 A，后方是物品 B，并且不同物品之间不会互相覆盖或消失。

### 2. 生产设备输入库存

在 `PlacedBuilding` 上增加输入库存状态：

- `inputItemId`
- `inputItemCount`
- `maxInputItemCount = 50`

并增加库存判断与操作方法：

- `canAcceptInputItem`
- `acceptInputItem`
- `hasInputItems`
- `consumeInputItems`

规则为：

- 输入槽最多 50 个物品。
- 输入槽为空时可以接收任意非空物品。
- 输入槽已有物品时，只能继续叠加相同物品。
- 类型不一致或数量已满时，传送带不能继续向设备输入。

### 3. 传送带到设备输入口的自动转移

在 `CanvasEditorState._onBeltTick` 中增加设备输入口检测逻辑：

- 传送带终点连接设备输入端口时，查找对应 `PlacedBuilding`。
- 检查当前最下游物品是否能被设备接收。
- 如果能接收，则从传送带移除一个到达输出端的物品，并写入设备输入库存。
- 如果不能接收，则设置传送带终端限制，让物品停在设备输入口前一格。

相关行为：

- 输入端口位于 `(0, 0)` 时，阻塞物品会停在 `(0, 1)`。
- 不会先进入 `(0, 0)` 再跳回。
- 不会在阻塞后继续循环播放传输动画。

### 4. 自然停止动画

为避免物品突然刷新到停止位置，冻结状态使用两段式处理：

- `freezeProgress = -1.0` 表示等待自然到达停止点。
- 当渲染进度达到停止点后，再转换为 `freezeProgress = 0.5`。

渲染器现在不再只依赖“断头传送带”判断冻结，而是会尊重物品段自身携带的 `freezeProgress`。

因此以下场景都会自然停止：

- 断头传送带末端。
- 前方已有停止队列。
- 设备输入满。
- 设备输入物品类型不一致。

### 5. 截断创建传送带时保留物品

当从已有传送带中间创建新传送带时，使用用户点击的分叉点作为截断点。

处理规则：

- 分叉点之前的路径归属新创建传送带。
- 分叉点之后的旧路径被拆分为下游传送带。
- 如果截断处或分叉点前存在物品，该物品会跟随新传送带。
- 下游仍存在的物品会保留在被拆出的旧传送带段中。

为此增强了物品段裁剪方法：

- `clippedItemSegments(start, end)`
- `shiftedItemSegments(offset)`

并支持在重新分配到新传送带时清除旧的冻结状态，避免旧传送带的停止帧污染新传送带。

### 6. 清除过期冻结状态

本次特别修复了一个截断创建后的动画问题：

旧传送带如果已经停止，新建传送带继承物品时不能继承旧的 `freezeProgress`，否则会出现“物品数量继续填充，但画面仍停在旧停止帧”的情况。

当前规则：

- 截断、合并、延长创建新传送带时，复制到新传送带的物品段会清除旧冻结状态。
- 被切出来的下游传送带段也会清除旧冻结状态。
- 同类物品继续从源头填充时，如果该段之前处于冻结状态，会自动解除冻结。

### 7. 端口连接状态与输入端残段修复

本轮继续修复了截断创建后设备端口状态不一致的问题。

问题表现为：

- 在设备输入端口前一格截断创建传送带后，画布上的端口高亮已经消失，但设备弹窗仍显示输入端处于连接状态。
- 输入端口格上仍残留半截传送带。这个半截传送带原本用于连接设备端口时的视觉裁剪，但断开后不应继续保留。

修复规则：

- 输入端口只在传送带终点接入时算连接。
- 输出端口只在传送带起点接出时算连接。
- 单格传送带残段不再视为有效端口连接。
- 截断创建后，如果下游只剩一个输入端口格，则把它视为断开后的视觉残段，不再保留为传送带。
- 设备弹窗中的端口连接状态复用 `PlacedBuilding.conveyorPortConnections`，避免画布和弹窗使用两套判断逻辑。

### 8. 创建模式下的动态预览与物品继承

本轮还修复了创建传送带时预览层与正式传输状态不同步的问题。

问题表现为：

- 截断创建预览时，旧传送带上的物品会在预览阶段消失。
- 已确认段和蓝色实时预览段只是静态 SVG 叠加，不会像正式传送带一样播放动态箭头。
- 截断创建时，只有退出创建模式后，物品才会沿新创建的传送带移动；在仍处于创建模式并准备创建下一段时，已确认段没有表现为运行中的传送带。
- 截断创建第一段后，旧传送带和新创建传送带的正式数据已经发生变化，但预览层仍按旧的临时投射逻辑覆盖画面，导致物品看起来全部消失或不继续传输。

修复规则：

- 预览层接收当前 `beltArrowController.value`，蓝色实时预览段会播放动态前景。
- 蓝色预览传送带的指针资源改为深灰色，和正式传送带的黄色指针区分。
- 创建第一段前，旧传送带保持原方向正常运输。
- 创建第一段后，该段会立即提交为正式 `ConveyorBelt`，并把创建会话保留在当前锚点继续绘制下一段。
- 已正式提交的段不再由“已确认预览层”重复渲染，而是直接由正式传送带渲染与 tick 驱动：
  - 分叉点之前的旧路径和新建第一段合并为新的正式传送带。
  - 被截断后的旧上方段保留已经存在的物品，但不会再从下方源头获得新物品。
  - 新传送带会在不退出创建模式的情况下继续接收源头物品，并沿刚创建的第一段移动到终点。
  - 后续继续点击创建下一段时，会用更长的新正式传送带替换上一条已提交的临时正式带，并继承已有物品队列。
- 已正式提交后，如果鼠标仍停在当前端点，不再绘制单格蓝色预览覆盖正式传送带，避免物品被预览层遮住。

### 9. 不可变物品段列表崩溃修复

在一次回退并重新编译后，创建截断传送带时出现：

```text
Another exception was thrown: Unsupported operation: sort
```

并导致设备、传送带和预览整体消失。

原因是临时裁剪传送带使用了 `const []` 作为 `itemSegments`。渲染过程中 `ConveyorBelt.ensureItemSegmentsFromLegacy()` 会对 `itemSegments` 排序，而不可变列表不能执行 `sort`。

修复规则：

- 临时空物品段使用可变列表 `<ConveyorItemSegment>[]`。
- `ConveyorBelt` 构造函数会复制传入的 `itemSegments`，即使外部误传不可变列表，模型内部也会持有可变副本。
- 新增回归测试，验证传入 `const []` 后调用排序相关逻辑不会崩溃。

## 测试覆盖

新增和强化的测试主要位于 `test/models/project_test.dart`。

覆盖场景包括：

- 设备输入库存最多接收 50 个同类物品。
- 设备输入库存不接收不同类型物品。
- 消耗输入物品后正确清空输入槽。
- 队列物品会停在阻塞终端前。
- 截断创建时，分叉点上的物品归属新传送带。
- 移除一个已经到达输出端的物品时，后续队列仍保留。
- 重新分配物品段时可以清除旧冻结状态。
- 冻结中的同类物品继续填充时会解除冻结。
- 输入端口只剩端口格单格残段时不再显示连接。
- 输出端口必须由传送带起点接出才显示连接。
- 截断创建后不会保留孤立的输入端口传送带残段。
- 截断创建第一段后会立即提交正式传送带，并在继续创建状态下保持物品传输。
- `ConveyorBelt` 构造时会复制不可变 `itemSegments`，避免后续排序崩溃。

## 后续注意事项

- 以后如果继续扩展多输入槽设备，需要把 `PlacedBuilding` 当前的单输入库存结构扩展为输入槽数组。
- 传送带动画停止判断应优先看物品段状态，而不是只看传送带是否断头。
- 对传送带进行拆分、合并、延长时，要特别注意 `fillCount`、`drainCount` 和 `freezeProgress` 是否仍然适用于新路径。
- `freezeProgress` 是动画状态，不应作为物品逻辑流动的唯一判断依据。
- 端口连接状态应统一使用 `PlacedBuilding.conveyorPortConnections`，不要在画布、弹窗或其它 UI 中重新手写“端点贴近端口”的判断。
- 创建模式中尚未确认的蓝色实时段仍是临时视觉状态；已经点击确认的段会立即写入正式工程数据，并由正式 tick/渲染逻辑驱动物品。
- 继续创建时如果要延长已确认路径，应优先替换上一条“已提交但仍在创建中的正式传送带”，并继承其物品队列，避免用预览层模拟正式传输。
- 传入 `ConveyorBelt` 的列表型状态必须保持可变，或者在构造函数中复制，避免渲染 tick 中排序、合并时触发不可变列表异常。
