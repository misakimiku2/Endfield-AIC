### 10. 策略模式简化（已完成）

原计划引入 `BuildingPanelBuilder` 抽象接口，实际采用更简洁的方式：在 `_BuildingDetailDialogState.build()` 中根据 building ID 直接创建对应面板 Widget。3 种面板类型不需要抽象接口的开销。

```dart
// 替代 _buildSynthesisPanel 调度方法
child: _isDepotUnloader
    ? DepotUnloaderPanel(...)
    : _isDepotLoader
        ? DepotLoaderPanel(...)
        : DefaultSynthesisPanel(...),
```

移除的布尔标志：
- `_isDepotAccess` getter（未使用）
- `_isLiquidMode`、`_isLiquidHover`、`_liquidSwitchSvgString`、`_liquidSwitchOffSvgString`（移入 DefaultSynthesisPanel）
- `_activeRecipe` getter（移入 DefaultSynthesisPanel）

保留的判断：
- `_isDepotUnloader`、`_isDepotLoader` getter（用于面板选择和资源网格 addIcon 判断）

## 后续新增设备弹窗指南

### 当前架构

重构后，`_BuildingDetailDialogState.build()` 中通过 building ID 三元表达式选择面板：

```dart
child: _isDepotUnloader
    ? DepotUnloaderPanel(...)
    : _isDepotLoader
        ? DepotLoaderPanel(...)
        : DefaultSynthesisPanel(...),
```

### 新增设备类型的步骤

**情况 A：新设备使用现有面板样式（合成/仓库）**

无需修改面板代码，只需在 `data_loader.dart` 中为新 building ID 配置配方数据，`DefaultSynthesisPanel` 会自动通过 `getRecipesForBuilding(buildingId)` 加载对应配方。

**情况 B：新设备需要全新面板样式**

1. 新建 `building_xxx_panel.dart`，实现面板 Widget（参考 `DepotLoaderPanel` / `DefaultSynthesisPanel` 的参数模式）
2. 在 `_BuildingDetailDialogState` 中添加判断 getter：
   ```dart
   bool get _isXxx => widget.placedBuilding.building.id == 'xxx_id';
   ```
3. 在 `build()` 的三元表达式中增加分支：
   ```dart
   child: _isDepotUnloader
       ? DepotUnloaderPanel(...)
       : _isDepotLoader
           ? DepotLoaderPanel(...)
           : _isXxx
               ? XxxPanel(...)
               : DefaultSynthesisPanel(...),
   ```
4. 如果新面板需要资源面板的交互（如添加物品），在 `_buildResourcePanel` 中补充对应的 `showAddIcon` / `onAddItem` 判断

**何时引入策略模式：** 当面板类型超过 5 种、或面板选择逻辑变得复杂时，再考虑引入 `BuildingPanelBuilder` 抽象接口 + 注册表模式。当前 3 种面板用三元表达式足够清晰。
