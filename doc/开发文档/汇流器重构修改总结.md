# 汇流器（Converger）全面重构修改总结

## 修改日期
- 初版重构：2026-06-22
- **简化重构（当前版本）**：2026-06-24

## 修改背景

汇流器（Converger）是与分流器功能完全相反的物流工具：3条输入传送带汇流至1条输出传送带。输入端为左、上、右三个方向，输出端为下方，处理速度0.5单位/秒（与传送带一致）。

### 初版重构问题（2026-06-22）

初版实现引入了过度复杂的机制，导致连接汇流器的传送带出现多种动画bug：
1. **输入端物品变箭头**：物品进入汇流器时短暂变成箭头再变回物品图片
2. **输出端物品分批次移动**：紧密排列的物品出现"第一个先走→后面几个停住→突然刷新跟上"的卡顿现象
3. **FCFS逻辑异常**：一个方向开始处理后其他方向传送带完全停止，物品无法到达汇流器入口参与排队

### 问题根因分析

初版实现的过度设计：
1. **convergerBuffer 内部缓冲槽位**：试图在汇流器内部存储1个物品，导致物品需要"先进入缓冲→再推送到输出带"两步走，破坏了动画连续性
2. **skipAdvanceOnce 延迟标记**：推送物品后让物品在position 0（建筑遮挡格）额外停留一个tick，导致物品停顿和箭头闪烁
3. **isInputToConverger 特殊推进顺序**：对汇流器输入带采用"先消费再推进"的特殊顺序，与其他设备不一致，导致物品位置计算异常
4. **错误的门控逻辑**：_canBeltOutputEnterBuilding 中检查输出带起始端空间，导致汇流器忙碌时其他方向物品被冻结在倒数第二格，无法到达入口参与FCFS排队
5. **输出带源拉取逻辑**：将汇流器作为输出带的"持续生产者"，增加了不必要的状态复杂度

### 用户期望的行为模型（2026-06-24 明确）

> "当左边输入端传送带的物品1进入到汇流器后，其实运行速度是跟'创建了一格→↓方向的转角传送带'是一样的，只需要把这个物品正常的像转角传送带一样自然的推到下方的输出端即可，并且在这个过程中，其他上、右的传送带就把汇流器这一格当作堵塞，等到物品1走出汇流器这一格之后，左边传送带就会收到堵塞的信号，上方的传送带的堵塞信号消失，上方传送带就会自然的把物品2推入到汇流器往下移动。"

**核心模型：汇流器 = 单通道虚拟转角**。汇流器不是一个有内部存储的"设备"，而是一个让3条输入带轮流通过的"交通指挥"，物品通过它的速度和在普通传送带上完全一致。

#### 关键逻辑修改

**(1) _canBeltOutputEnterBuilding 门控修正**

```dart
// 2026-06-24 简化后：只要输出带存在，就允许物品到达末端排队
// 真正的推送门控（FCFS顺序、汇流器空闲、输出带空间）在_transferBeltOutputToBuilding中检查
if (building.isConverger) {
  final outputBelt = _getBeltForConvergerOutputDirection(building);
  return outputBelt != null;
}
```

**关键点**：门控只检查输出带是否存在，**不检查FCFS顺序、不检查输出带是否有空间**。这确保了：
- 所有方向的物品都能到达传送带末端（汇流器入口）
- 物品到达末端后被 `_findEarliestArrivalConvergerDirection` 检测到，分配FCFS序号
- 只有在实际尝试推送时才做双重检查

**(2) _isConvergerReadyForNextItem 空闲判断**

```dart
/// 判断汇流器输出带是否准备好接收下一个物品（上一个物品已走出遮挡格）
bool _isConvergerReadyForNextItem(ConveyorBelt outputBelt) {
  outputBelt.ensureItemSegmentsFromLegacy();
  if (outputBelt.itemSegments.isEmpty) return true;
  final first = outputBelt.itemSegments.first;
  return first.drainCount >= 1;
}
```

**关键点**：不是用 `canAcceptNewItemFromStart` 判断（那会检查fillCount >= limit，过于严格），而是检查第一个物品段的drainCount >= 1，确保物品已经走出汇流器遮挡格（position 0），下一个物品才可以进入。这精确实现了用户描述的"等到物品1走出汇流器这一格之后"。

**(3) _transferBeltOutputToBuilding 汇流器分支**

```dart
if (building.isConverger) {
  final arrivalDir = _beltArrivalDirection(belt);
  if (arrivalDir == null) return false;
  final inputPort = _arrivalDirToInputPort(arrivalDir);

  // FCFS：选择物品最早到达末端的方向
  final earliestDir = _findEarliestArrivalConvergerDirection(building);
  if (earliestDir == null) return false;
  if (inputPort != earliestDir) return false; // 不是最早到达，在末端等待

  final outputBelt = _getBeltForConvergerOutputDirection(building);
  if (outputBelt == null) return false;

  // 关键：检查上一个物品是否已走出遮挡格
  if (!_isConvergerReadyForNextItem(outputBelt)) return false;

  final terminalLimit = _calculateBeltTerminalLimit(outputBelt);
  // 关键：不使用 skipAdvanceOnce！物品直接开始平滑移动
  if (outputBelt.pushSourceItem(itemId, terminalLimit: terminalLimit)) {
    belt.removeOutputReadyItem();
    building.convergerArrivalTimestamps.remove(inputPort);
    return true;
  }
  return false;
}
```

**关键改动**：
- ✅ **无内部缓冲**：物品直接从输入带推送到输出带，失败则下次重试
- ✅ **无 skipAdvanceOnce**：pushSourceItem 不使用该参数，物品推送后直接开始平滑移动
- ✅ **精确空闲判断**：使用 `_isConvergerReadyForNextItem` 而非 `canAcceptNewItemFromStart`

**(4) _tickSingleBeltOnce 统一处理顺序**

- ❌ 移除 `isInputToConverger` 变量
- ❌ 移除"先消费再推进"的特殊分支
- ❌ 移除 `activeSourceItemId` 中的 `!isInputToConverger` 条件
- ✅ 所有设备输入带统一使用"先推进再消费"顺序
- ✅ 移除 sourceBuilding 判断中的 `sourceBuilding.isConverger` 条件（汇流器不再作为输出带的持续源）

**(5) 输出带源拉取逻辑移除**

- ❌ `_getAvailableOutputItemIdForBeltStart` 中汇流器分支完全移除
- ❌ `_consumeOutputItemForBeltStart` 中汇流器分支完全移除

**原因**：汇流器采用"纯推送式"架构——物品是在 `_transferBeltOutputToBuilding` 中被一次性直接 push 到输出带的 itemSegments 中，输出带正常推进即可，不需要汇流器作为"源建筑"持续提供物品。这与分流器的处理方式一致。

#### FCFS（先到先得）机制（保留并简化）

汇流器采用 FCFS 排队机制：

1. **到达序号分配**：当物品到达传送带末端（`outputReadyItemId()` 返回非空）时，`_findEarliestArrivalConvergerDirection` 为该方向分配递增序号，存入 `convergerArrivalTimestamps`
2. **优先处理**：每次处理时选择序号最小（最早到达）的方向
3. **末端等待**：非最早到达方向的物品在传送带末端等待（inputBlocked=false，物品可以到达末端但不会被推送）
4. **序号清理**：物品被成功推送后清除该方向的到达序号；物品不再在末端时自动清理过期序号

#### 仿真架构（当前版本）

- 汇流器状态由主线程管理，Isolate 跳过覆盖
- **纯推送式架构**：物品直接从输入带推送到输出带，**无内部缓冲**
- **无 skipAdvanceOnce**：物品推送后直接开始平滑移动，不在遮挡格额外停留
- **精确空闲判断**：上一个物品走出遮挡格（drainCount >= 1）后下一个才能进入
- **正确门控**：所有方向物品都能到达入口排队，FCFS决定处理顺序

## 验证要点（2026-06-24 更新）

### 核心功能
1. ✅ 单输入场景：1条输入带 → 汇流器 → 1条输出带，物品平滑通过，无箭头闪烁、无停顿
2. ✅ 三输入场景：3条输入带 → 汇流器 → 1条输出带，物品按到达顺序（FCFS）轮流通过
3. ✅ 物品到达末端排队：所有方向物品都能到达汇流器入口等待，不会提前停住
4. ✅ 输出带物品队列：多个物品连续通过时，输出带物品紧密排列、连续移动，无分批次卡顿
5. ✅ 单通道：同一时间只有一个物品穿越汇流器，其他方向在入口等待
6. ✅ 输出带堵塞：输出带满时，输入物品在入口排队，输出带有空间后自动恢复

### 边界场景
7. 双输入场景：2条输入带按FCFS顺序轮流处理
8. 传送带创建：从汇流器格子只能向下创建传送带
9. 传送带吸附：从上方/右方/左方创建传送带到汇流器时正确连接
10. 多条输入带终点共存：3条传送带终点均在汇流器格子，互不截断
11. 弹窗面板：正确显示3输入1输出状态
12. SVG渲染：图标正确显示，无BG背景遮挡

### 回归测试
13. 分流器（Splitter）：物品分流动画正常，无回归
14. 物流桥：跨层传输正常
15. 转角传送带：物品平滑转弯
16. 冶炼炉等生产设备：输入输出正常
