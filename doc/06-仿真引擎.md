# 06 — 仿真引擎

> 对应文件：`lib/canvas/simulation_engine.dart` + `sim_worker.dart` + `sim_protocol.dart`

仿真引擎采用 **Isolate 双线程模型**：原生平台通过独立 Isolate 以 20Hz 推进生产 tick，主线程不阻塞；Web 平台自动回退到主线程定时器。两套路径共享相同的生产逻辑。

## 6.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│  主线程                                                      │
│  ┌─────────────────────────────────────────────────────┐    │
│  │ SimulationEngine extends ChangeNotifier              │    │
│  │  ├─ _project (ProjectState)                          │    │
│  │  ├─ _dataLoader                                      │    │
│  │  ├─ _isolate / _workerSendPort / _mainReceivePort    │    │
│  │  ├─ _syncRevision（同步版本号）                       │    │
│  │  ├─ _fallbackTimer（Web 回退）                        │    │
│  │  └─ notifyListeners() → UI 重绘                       │    │
│  └────────┬──────────────────────────────┬───────────────┘    │
│           │ sync/start/stop/setSpeed     │ SimTickResult      │
│           ▼                              ▲                    │
│  ┌────────────────────┐                  │                    │
│  │ SendPort           │                  │                    │
│  └────────────────────┘                  │                    │
└──────────────────────────────────────────┼────────────────────┘
                                           │
┌──────────────────────────────────────────▼────────────────────┐
│  Isolate (sim_worker.dart)                                     │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │ simWorkerEntry(mainSendPort) → _SimWorker                │  │
│  │  ├─ _buildings / _conveyors / _recipes（状态副本）        │  │

│  └─────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────┘
```

## 6.2 `sim_protocol.dart` — Isolate 通信协议

定义主 Isolate 与计算 Isolate 之间通信的全部可序列化数据结构（纯数据 DTO，含 JSON 双向转换）。

### 数据类一览

| 类名 | 职责 | 关键字段 |
|------|------|----------|
| `SimSyncState` | 主→计算 Isolate 的完整状态同步包 | `revision`, `buildings`, `conveyors`, `recipes`, `speedMultiplier` |
| `SimBuildingData` | 设备的可序列化数据 | `id`, `buildingId`, `gridX/Y`, `rotation`, `activeRecipeId`, `depotOutputItemId`, `inputItemId`, `inputItemCount`, `outputItems: Map<String,int>`, `gridWidth/Height`, `inputPorts`, `outputPorts`, `isPaused` |
| `SimPortData` | 端口数据 | `index`, `type`, `relativeX/Y`, `direction`, `portType` |
| `SimConveyorData` | 传送带数据 | `id`, `path: List<Offset>`, `itemId`, `flowProgress`, `itemFillCount`, `itemDrainCount`, `isBlocked`, `forcedDirection`, `incomingDirection`, `lastItemFillCount/DrainCount`, `deadEndFreezeProgress`, `lastItemFreezeProgress` |
| `SimRecipeData` | 配方数据 | `id`, `processTimeSeconds`, `inputs`, `outputs`, `allowedBuildings` |
| `SimRecipeIOData` | 配方输入输出项 | `itemId`, `amount` |
| `SimTickResult` | 计算→主 Isolate 的单次 tick 结果 | `revision`, `buildings: List<SimBuildingResult>`, `conveyors: List<SimConveyorResult>` |
| `SimBuildingResult` | 设备 tick 结果（轻量） | `id`, `isBlocked`, `productionProgress`, `inputItemId`, `inputItemCount`, `activeRecipeId`, `outputItems` |
| `SimConveyorResult` | 传送带 tick 结果 | `id`, `itemId`, `flowProgress`, `itemFillCount`, `itemDrainCount`, `isBlocked`, `lastItemFillCount/DrainCount`, `deadEndFreezeProgress`, `lastItemFreezeProgress` |
| `SimControlMessage` | 控制消息封装 | `type`（`'sync'`/`'start'`/`'stop'`/`'setSpeed'`）, `data` |

每个类都提供 `Map<String,dynamic> toJson()` 与 `factory .fromJson(Map)` 方法。

> **注意**：`SimConveyorData.path` 在 JSON 中序列化为 `[{'x':..., 'y':...}]`，反序列化时还原为 `Offset`（依赖 `dart:ui`）。

## 6.3 `sim_worker.dart` — 计算 Isolate

计算 Isolate 的入口函数与工作器实现，持有状态副本并以 20Hz 独立计算 tick，将结果回传主 Isolate。

### 入口函数

```dart
void simWorkerEntry(SendPort mainSendPort)  // 必须是顶层/静态，供 Isolate.spawn 调用
```

创建 `_SimWorker` 并 `_init()`。

### `_SimWorker`（私有类）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_mainSendPort` | `SendPort` | 主 Isolate 的发送端口 |
| `_receivePort` | `ReceivePort` | 接收主 Isolate 消息的端口 |
| `_tickTimer` | `Timer?` | 20Hz 周期定时器 |
| `_buildings` / `_conveyors` / `_recipes` | `List<...>` | Isolate 持有的状态副本 |
| `_speedMultiplier` | `double` | 速度倍率 |
| `_revision` | `int` | 同步版本号（与主 Isolate 对齐） |
| `_isRunning` | `bool` | 是否在 tick |
| `_tickRate` | `double` (const) | 20.0 |
| `_cellSize` | `double` (const) | 48.0 |
| `_portConnectionThreshold` | `double` (const) | 30.0 端口连接判定距离 |
| `_buildingBlocked` / `_buildingProgress` | `Map<String,bool>` / `Map<String,double>` | 临时计算结果缓存 |

### 关键方法

- `void _init()` — 创建 ReceivePort → 将其 sendPort 发回主 Isolate（建立双向通道）→ 监听消息
- `void _onMessage(dynamic)` — 消息分发：`sync`/`start`/`stop`/`setSpeed`
- `void _onSync(Map)` — 用 `SimSyncState.fromJson` 替换本地状态副本与 revision
- `void _onStart()` / `_onStop()` — 启停 20Hz Timer
- `void _onTick()` — **tick 循环核心**：
  ```
  dt = _speedMultiplier / _tickRate
  _updateConveyors(dt)
  _updateBuildings(dt)
  构造 SimTickResult（含 revision）
  _mainSendPort.send(result.toJson())
  ```
- `void _updateConveyors(double dt)` — 更新每条传送带 `flowProgress += dt*60`，并根据源设备阻塞状态设置 `isBlocked`
- `void _updateBuildings(double dt)` — 设备生产循环：仓库取货口特殊处理 → 自动匹配配方 → 检查可接受输出/输入可用 → 消耗输入 → 累加 progress → progress≥1 时产出物品到 `outputItems`
- `void _produceDepotOutput(SimBuildingData)` — 仓库取货口将 `depotOutputItemId` 推送到连接的传送带
- `void _pushOutputToBelts(SimBuildingData, int)` — 按端口 index 对应配方 outputs 顺序，将输出库存推送到连接传送带
- `bool _canAcceptRecipeOutputs(...)` / `_checkInputsAvailable(...)` / `_consumeInputs(...)` / `_findMatchingRecipe(...)` — 生产前置检查与消耗
- `SimBuildingData? _findSourceBuilding(Offset)` — 根据世界坐标查找源设备
- `Offset _portWorldPosition(SimPortData, SimBuildingData)` — 计算端口旋转后的世界坐标（含 rotation%4 的四象限旋转矩阵）
- `Offset _beltStart(SimConveyorData)` / `_beltEnd(...)` — 传送带首/末格世界坐标
- `bool _hasOutputSpace(SimConveyorData)` / `_hasStoppedLastItems(...)` — 传送带是否有空间接收新物品

### Isolate 通信机制

1. 主 Isolate 调用 `Isolate.spawn(simWorkerEntry, mainReceivePort.sendPort)` 启动 worker
2. worker `_init` 创建自己的 `ReceivePort`，将其 `sendPort` 通过 `_mainSendPort.send(...)` 回传
3. 主 Isolate 在 `_onMessageFromWorker` 收到 `SendPort` 后存为 `_workerSendPort`，标记 `_isolateReady=true`，并立即 `_syncState()`
4. 此后双向通信：
   - 主→worker：`_workerSendPort.send({'type':..., 'data':...})`（sync/start/stop/setSpeed）
   - worker→主：`_mainSendPort.send(result.toJson())`（每 tick 一次 `SimTickResult`）
5. worker 用 `_revision` 字段标记每次同步版本，主 Isolate 收到结果时校验 `result.revision == _syncRevision`，过期结果丢弃

## 6.4 `simulation_engine.dart` — 仿真引擎主线程侧

封装 Isolate 生命周期、状态同步、tick 结果应用，并提供 Web 平台主线程回退。

### `SimulationEngine extends ChangeNotifier`

被 UI 层 listen 以触发重绘。

| 字段 | 类型 | 说明 |
|------|------|------|
| `_dataLoader` | `DataLoader` | 配方/建筑数据源 |
| `_project` | `ProjectState?` | 当前工程状态（主线程权威） |
| `_isRunning` | `bool` | 是否运行中 |
| `_speedMultiplier` | `double` | 速度倍率（setter 内 clamp 0.25~10，并 sendControl + notifyListeners） |
| `_syncRevision` | `int` | 同步版本号（每次 _syncState 自增） |
| `_isolate` | `Isolate?` | 计算 Isolate 实例 |
| `_workerSendPort` | `SendPort?` | 发往 worker 的端口 |
| `_mainReceivePort` | `ReceivePort?` | 接收 worker 消息的端口 |
| `_mainSubscription` | `StreamSubscription?` | 监听订阅 |
| `_isolateReady` | `bool` | Isolate 是否就绪 |
| `_fallbackTimer` | `Timer?` | Web 平台主线程定时器 |
| `_tickRate` / `_cellSize` / `_portConnectionThreshold` | `double` (const) | 20.0 / 48.0 / 30.0 |

### 关键方法

- `Future<void> init()` — **平台分支**：`kIsWeb` 直接返回（用回退）；否则 `Isolate.spawn(simWorkerEntry, _mainReceivePort!.sendPort)`，失败则清理并回退
- `void _onMessageFromWorker(dynamic)` — **消息处理**：
  - 收到 `SendPort` → 标记就绪 + `_syncState()`
  - 收到 `Map` → `SimTickResult.fromJson` → 校验 revision → `_applyTickResult` → `notifyListeners()`
- `void _applyTickResult(SimTickResult)` — **结果应用**：
  - 遍历 `buildings` 更新 `pb.isBlocked/productionProgress/inputItemId/inputItemCount/activeRecipeId/outputItems`
  - 遍历 `conveyors` 更新 `flowProgress/isBlocked`（有 itemSegments 时仅更新这两项，**避免覆盖残留物品**）
- `void attach(ProjectState)` — 绑定工程，若 Isolate 就绪则 `_syncState()`
- `void _syncState()` — **状态同步**：
  ```
  _syncRevision++
  将 _project 的 buildings/conveyors/recipes 转为 SimSyncState
    （含端口旋转后的相对坐标、depotOutputItemId、isPaused 等）
  _sendControl('sync', state.toJson())
  ```
- `void start()` / `stop()` / `toggle()` — 启停控制：Isolate 就绪则 sendControl，否则启停 `_fallbackTimer`
- `void _sendControl(String type, [Map? data])` — `_workerSendPort?.send({'type':type,'data':data})`
- `String? _outputItemIdForBeltStart(ConveyorBelt)` — 查找传送带起点对应的设备输出物品 ID（用于主线程判断）
- `@visibleForTesting void debugTickForTesting(double dt)` — 测试钩子
- `void dispose()` — stop + 取消订阅 + 关闭端口 + `_isolate.kill(priority: Isolate.immediate)`

### Web 回退方法组

与 worker 逻辑镜像，在主线程直接修改 `_project`：

- `_onFallbackTick` / `_fallbackUpdateConveyors` / `_fallbackUpdateBuildings`
- `_fallbackAutoSelectRecipe` / `_fallbackProduceDepotOutput`
- `_fallbackCheckInputsAvailable` / `_fallbackConsumeInputs` / `_fallbackCanAcceptRecipeOutputs`
- `_fallbackPushOutputToBelts` / `_fallbackFindSourceBuilding`

## 6.5 生产循环逻辑

`_updateBuildings(dt)` / `_fallbackUpdateBuildings(dt)` 共享相同的生产逻辑：

```
对每个建筑 pb:
  若 pb.isPaused → 跳过生产（但仍接收输入）
  若 pb 是仓库取货口（depot_unloader）→ _produceDepotOutput
  否则:
    1. 自动匹配配方（若 activeRecipeId 为空，根据 inputItemId 查找）
    2. 检查输出空间（_canAcceptRecipeOutputs）
    3. 检查输入可用（_checkInputsAvailable）
    4. 消耗输入（_consumeInputs）
    5. 累加 progress += dt / processTimeSeconds
    6. 若 progress ≥ 1:
       - 产出物品到 outputItems
       - progress -= 1（保留余数）
       - 尝试推送到连接传送带（_pushOutputToBelts）
    7. 推送输出库存到传送带（_pushOutputToBelts）
```

### 关键约束（来自项目记忆）

- 精炼炉必须有输出库存（`outputItems`）最大容量 50，解耦生产与传送带可用性
- 精炼炉只要输入物品可用且输出库存未满就继续生产
- 设备输入物品接收即使生产暂停（`isPaused = true`）也继续
- 设备 UI 状态优先级：暂停 > 阻塞 > 正常生产
- 设备阻塞状态触发条件：输入满 OR 输出满（`isInputFull || isOutputFull`）

## 6.6 revision 一致性机制

`SimulationEngine._syncState` 每次自增 `_syncRevision` 并随同步包发送；worker 在结果中回传相同 revision；主线程只应用 `result.revision == _syncRevision` 的结果，保证过期数据不会覆盖最新状态。

```
主线程 _syncRevision = 5 → 发送 sync(rev=5)
用户放置新建筑 → _syncRevision = 6 → 发送 sync(rev=6)
worker 仍在处理 rev=5 → 回传 result(rev=5)
主线程收到 result(rev=5) → 5 ≠ 6 → 丢弃
worker 收到 sync(rev=6) → 替换副本
worker 回传 result(rev=6) → 主线程应用
```

## 6.7 双 tick 机制并存

项目存在两套并行的 tick 机制，通过 `ProjectState` 的不同字段分工：

| 机制 | 驱动方式 | 频率 | 负责字段 | 触发刷新 |
|------|----------|------|----------|----------|
| `CanvasEditor._onBeltAnimationFrame` | `AnimationController` (2s 循环) | 跨零触发 | `ConveyorBelt.itemSegments/itemFillCount/lastItemId`；`PlacedBuilding.inputItemCount/outputItems`（即时交互） | `setState` |
| `SimulationEngine` / `_SimWorker._onTick` | 20Hz 定时器 | 20Hz | `PlacedBuilding.productionProgress/outputItems/isBlocked/inputItemId/inputItemCount/activeRecipeId`；`ConveyorBelt.flowProgress/isBlocked` | `notifyListeners()` |

> **设计要点**：前者负责传送带物品的**逐格视觉推进**与建筑库存的**即时交互**（源消耗、终点入库）；后者负责建筑**配方生产进度**（progress 累加、产出物品到 outputItems）。两者通过 `ProjectState` 的字段分工，避免冲突。

## 6.8 平台分支

`SimulationEngine.init` 通过 `kIsWeb` 分支：

- **原生平台**：`Isolate.spawn(simWorkerEntry, ...)` 启动独立 Isolate 计算，主线程不阻塞。
- **Web 平台**：直接返回，使用 `_fallbackTimer` + 镜像逻辑的方法组在主线程运行。

两套路径共享相同的 `dt = _speedMultiplier / _tickRate` 公式与生产逻辑。
