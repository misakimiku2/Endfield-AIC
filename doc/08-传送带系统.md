# 08 — 传送带系统

> 对应文件：
> - `lib/AIC/Logistics Units/transport_belt.dart`（控制器，路径规划核心）
> - `lib/AIC/Logistics Units/transport_belt_renderer.dart`（渲染器）

传送带系统是项目最复杂的模块。`TransportBeltController` 负责创建/寻路/合并/截断/分叉/物流桥自动放置等全部状态与逻辑；`TransportBeltRenderer` 负责将传送带绘制到 Canvas。两者通过 `ConveyorBelt` 数据模型解耦。

---

## 8.1 `transport_belt.dart` — 传送带创建控制器

### 8.1.1 类职责

`TransportBeltController` 是传送带创建全流程控制器：处理点击/悬停/快捷键，寻路，自动检测交叉并放置物流桥，合并/截断/分叉旧传送带并继承物品状态。

### 8.1.2 依赖注入

通过构造函数注入：

```dart
TransportBeltController({
  required ProjectState project,
  required VoidCallback onProjectChanged,
  required VoidCallback onRebuildCache,
  required VoidCallback notifyListeners,
  required String? Function() currentPhase,
  required Building? Function(String buildingId) getBuilding,
})
```

### 8.1.3 状态字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `anchors` | `List<Offset>` | 用户点击的锚点序列 |
| `fullPath` | `List<Offset>` | 已确认的完整路径 |
| `confirmedPath` | `List<Offset>` | 预览时已确认段（fullPath 去尾） |
| `pathInvalid` | `bool` | 当前预览是否无效 |
| `previewPath` / `previewOccupied` / `previewContextExtension` / `previewBridgeCells` | — | 预览相关 |
| `mouseGridPos` | `Offset` | 当前鼠标格子 |
| `_mergeTarget` | `ConveyorBelt?` | 合并目标传送带 |
| `_startingPortDirection` / `_incomingDirection` | `String?` | 起始端口方向 / 首格入方向 |
| `_committedBeltId` / `_lastCommittedPathLength` | — | 连续创建模式下已提交的传送带 id 与长度 |
| `_truncatedBeltTail` | — | 截断创建时原传送带剩余格子（视为阻挡） |

**常量**：`_beltBridgeId='belt_bridge_1x1'`、`cellSize=48.0`

### 8.1.4 公开 API

```dart
void reset()                              // 清空所有状态
bool handleTap(Offset gridPos)            // 点击处理：首锚点走 _handleFirstAnchor，后续走 _handleSubsequentAnchor
void handleHover(Offset gridPos)          // 鼠标移动更新预览
void handleRightClick()                   // 右键完成/取消
bool handleKeyEscape()                    // ESC 完成/取消
```

### 8.1.5 首锚点处理

`bool _handleFirstAnchor(Offset gridPos)` — 按优先级判定起点：

1. **物流桥格子** → 允许任意方向开始
2. **传送带格子** → 单格传送带以其方向为起始方向；多格传送带截断创建，记录 `_truncatedBeltTail`
3. **设备内部格子** → 必须是输出端口才允许，记录 `_startingPortDirection`

### 8.1.6 后续锚点处理

`bool _handleSubsequentAnchor(Offset gridPos)` — 三种情况：

1. **点击某传送带起点（合并候选）** → 寻路 + `_isDirectionCompatible` 校验 → 自动 `_finish`
2. **点击某传送带中间格子（截断连接）** → 寻路 → 自动 `_finish`
3. **普通格子/输入端口/物流桥** → 寻路 → 转角吸附（`_findAdjacentBeltStart`）→ `_finish(keepCreating: true)` 或完成

> 输入端口作终点时要求 `_hasIndependentBeltCell`（设备端口间至少留 1 格传送带）。

### 8.1.7 完成与物品状态继承（核心复杂逻辑）

`void _finish({bool keepCreating = false})` — 创建新 `ConveyorBelt` 并处理旧传送带拆分：

1. 合并目标路径追加到 fullPath（跳过首格）
2. `_autoCreateBridgesAtCrossings()` 自动放置物流桥
3. 起点在物流桥时，`_findBridgeContinuationSourceBelt` 找到桥另一侧的源传送带并前置其路径
4. 起点在旧传送带中间时，记录 `forkSourceBelt` + `forkSourceIndex`
5. 终点在旧传送带中间时，方向兼容则追加下游（`endCellDownstreamMerged`）
6. **物品状态继承**（4 种来源）：
   - `committedSourceBelt`（加长断头）
   - `sourceBelt`（从终点延伸）
   - `forkSourceBelt`（分叉，用 `clippedItemSegments`）
   - `_mergeTarget`（合并，用 `shiftedItemSegments` 偏移 newSegmentLength-1）
   - 下游合并时也继承下游物品
7. 构造新 `ConveyorBelt`
8. 拆分旧传送带：
   - forkIdx 处的分叉 → 下游独立传送带
   - endCellBelt 截断 → 上游独立 + 下游独立（未合并时）
   - 移除 toRemove、添加 toAdd
9. `keepCreating=true` 时保留 `_committedBeltId` 继续创建

### 8.1.8 寻路算法（重点）

采用"**动量路径优先 + BFS 兜底**"的双策略。

#### `List<Offset>? _findPath(Offset start, Offset end, Set<String> blocked, {bool verticalFirst})`

寻路总入口：

1. 终点为设备输入端口时，递归寻路到端口前一格（`penultimate`），临时把终点加入 blocked 防止擦过/斜插
2. 仅首段（`anchors.length <= 1`）施加 `_startingPortDirection` 约束
3. 先尝试 `_calculateMomentumPath`（动量路径，优先直线/单次转弯）
4. 动量路径需通过 `_isPathValidAtBridges`（物流桥处直线）和 `_isPathValidAtBeltCrossings`（不平行重叠、交叉点直线）校验
5. 动量路径失败则回退到 `_findPathBFS`

#### `List<Offset> _calculateMomentumPath(start, end, {verticalFirst, startingDirection})`

启发式直角路径：先按 `startingDirection` 走一步，再按 `verticalFirst` 决定先走垂直还是水平，生成 L 形或直线路径。复杂度 O(|dx|+|dy|)。

#### `List<Offset>? _findPathBFS(start, end, blocked, {firstStepDirection})`

**BFS 寻路核心**：

- 方向偏移：up[0,-1] / right[1,0] / down[0,1] / left[-1,0]
- visited 用 `Map<String, (String? parentKey, Offset? parentCell)>`，**key 在物流桥/传送带交叉点处包含方向信息**（`x_y_dir`），允许不同方向到达同一格子
- 起点若有 `firstStepDirection` 约束则只走该方向
- **物流桥格子**：只允许沿入方向直线通过（`allowedDirIndices = [node.incomingDir]`）
- **传送带交叉点**：同样只允许直线通过（不能转弯）
- **平行重叠检查**：邻居是现有传送带且方向同向（都水平或都垂直）时阻止，除非邻居是终点且为合并候选
- 搜索上限 5000 节点防死循环
- 回溯路径时根据 `endUseDirKey` 选择带方向或不带方向的 key

### 8.1.9 物流桥逻辑（重点）

> **注意**：物流桥的轨道切换逻辑实际在 `transport_belt.dart`，而非 `belt_bridge.dart`（后者仅是 1x1 四向端口配置）。

#### `void _autoCreateBridgesAtCrossings()`

自动放置物流桥：

1. 遍历 fullPath 每格，对比所有现有传送带的同位置格子
2. 用 `_isPerpendicularCrossing(newDir, beltDir)` 判定垂直交叉（一水平一垂直）
3. 跳过已有物流桥的格子和转角传送带格子（`_isBeltCellTurn`）
4. 收集所有交叉点后，逐个创建 `PlacedBuilding`（id=`building_<timestamp>`，居中放置）加入 `project.buildings`
5. **不再拆分被交叉的传送带**——传送带保持完整路径穿过物流桥

#### `List<Offset> _computePreviewBridgeCells()`

预览版交叉检测，逻辑同上但不实际创建建筑，仅返回交叉点列表供渲染物流桥预览。

#### `bool _isPathValidAtBridges(List<Offset> path)`

验证路径在物流桥格子处前后方向一致（不能在物流桥内转弯）。

#### `bool _isPathValidAtBeltCrossings(List<Offset> path)`

验证路径不与现有传送带平行重叠，且在交叉点处保持直线；终点为合并候选时允许平行。

#### `bool _isBlockedBridgeStartSegment(List<Offset> segment)`

起点是物流桥且第二格是传送带时阻止（避免从桥直接撞上传送带）。

#### `PlacedBuilding? _findBeltBridgeAtCell(Offset)`

查找格子上的物流桥建筑。

#### `ConveyorBelt? _findBridgeContinuationSourceBelt(bridgeCell, outgoingDirection)`

找到以物流桥格子为终点、且在桥处方向与 `outgoingDirection` 一致的源传送带，用于桥接续。

### 8.1.10 辅助方法


## 8.2 `transport_belt_renderer.dart` — 传送带渲染器

用 SVG 图标绘制直线段/转弯段、物品图标、粒子动画、预览路径、阻塞指示，并管理物品 PNG 图片缓存。

### 8.2.1 关键字段

**颜色常量**：
- `_beltColor`、`_beltHighlight`、`_arrowColor`
- `_particleSize=3.0`、`_particleSpacing=16.0`
- `_previewFillColor`、`_previewBorderColor`、`_previewArrowColor`
- `_previewOccupiedFill/Border`、`_confirmedFillColor/LineColor/ArrowColor`

**SVG 缓存**：
- `_movePicture`、`_rotatePicture`、`_moveBluePicture`、`_rotateBluePicture`、`_moveRedPicture`、`_rotateRedPicture`
- `_pointerPicture`、`_previewPointerPicture`

**物品图片缓存**：
- `_itemImageCache`（`Map<String,ui.Image>`）
- `_itemImageLoading`（`Set<String>`）
- `onItemImageReady` 回调

**方向索引常量**：`_dirUp=0`、`_dirRight=1`、`_dirDown=2`、`_dirLeft=3`

### 8.2.2 关键方法

#### 初始化与端口判定

```dart
static Future<void> init()                                          // 加载 SVG 资源
static bool isOutputPort(Offset, List<PlacedBuilding>)              // 判断格子是否为设备输出端口
static bool isInputPort(Offset, List<PlacedBuilding>)               // 判断格子是否为设备输入端口
```

#### 裁剪与粒子过滤

```dart
static Rect? getLocalClipRect({
  path, index, cellSize, buildings,
  fullPathContext, contextStartIndex,
  forcedDirection, incomingDirection
})                                                                  // 计算单元格本地裁剪矩形
static bool _shouldDiscardParticle(particlePos, path, cellSize, buildings)  // 过滤端口处半段粒子
```

`getLocalClipRect` 用于让相邻格子无缝拼接：起点裁入方向反侧（端口处裁到 0，非端口裁到 -half），终点裁出方向侧。

#### 核心渲染入口

```dart
static void renderConveyorPath(
  Canvas, ConveyorBelt belt, Item? item, cellSize, buildings,
  {detailLevel, arrowProgress, lastItem, allItems,
   hideTerminalBackground, hiddenBackgroundCells}
)
```

**核心渲染流程**：

1. 检测断头（终点非输入端口）`isDeadEnd`
2. `belt.ensureItemSegmentsFromLegacy()` 同步旧字段到 segment 模型
3. 收集 `renderSegments`（有物品的段，按 drainCount 排序）
4. **断头冻结逻辑**：每段抵达前方阻挡位置后单独冻结 `freezeProgress`（-1.0 表示等待自然到位，≥0.5 时锁定为 0.5），避免多物品队列在断源/重连时重播
5. 计算 `effectiveArrowProgress`（冻结时用冻结值，否则用实时 arrowProgress）
6. 调用 `_renderWithSvg` 或回退到 `_drawConveyorCell`
7. LOD≥2 且无物品图片时画粒子动画 `_renderParticles`
8. 触发物品 PNG 异步加载 `_loadItemImage`
9. 阻塞时画 `_renderBlockedIndicator`（红圈+白叉）

#### SVG 单元格绘制

```dart
static void _renderWithSvg(...)                                    // 两趟绘制：背景 + 前景
static (bool, String, String, bool) _getCellTurnInfo(path, index, {incomingDirection, forcedDirection})
// 返回 (isTurn, incomingDir, outgoingDir, isCounterClockwise)
static void _drawSvgCellAtOrigin(Canvas, path, index, cellSize, {isPreview, isOccupied, fullPathContext, contextStartIndex, forcedDirection, incomingDirection, arrowProgress, drawBackground, drawPointer, itemImage})
```

`_getCellTurnInfo` 判定逻辑：
- 单格、首格（用 incomingDirection）、末格（用 forcedDirection）、中间格四种情况
- 用 `(outIdx - inIdx + 4) % 4 == 3` 判定逆时针

`_drawSvgCellAtOrigin` 绘制：
- **直线段**：按方向旋转 `dirIdx * π/2`
- **转弯段**：顺时针用 `outgoingAngle`，逆时针用 `(outAngle - π + 2π) % 2π` + 水平镜像
- **前景物品/指针**：
  - 转弯时按圆弧路径计算位置 `(pivotX + 0.5*cos(currentAngle), pivotY + 0.5*sin(currentAngle))`，切线角 `currentAngle + deltaAngle`
  - 直线时按 `(0.5 - progress) * cellSize` 平移

#### 预览渲染

```dart
static void renderPreviewPath(...)                                 // 预览路径
static void renderConfirmedPreviewPath(...)                        // 已确认预览
static void renderBlockedBeltCells(...)                            // 阻塞格子
static void renderHoverHighlight(...)                              // 悬停高亮
```

#### 辅助方法

```dart

static Future<void> _loadItemImage(String assetPath)               // 异步加载物品 PNG
```

## 8.3 关键设计要点

### 8.3.1 死胡同冻结机制

当传送带终点不是设备输入端口时（死胡同），物品必须在末端停止，不能继续动画。`ConveyorBelt.freezeDeadEndSegments()` 设置 `freezeProgress = -1.0` 等待渲染器平滑推进；渲染器在每段抵达前方阻挡位置后单独冻结，≥0.5 时锁定为 0.5。

### 8.3.2 物品段模型

`ConveyorItemSegment` 表示传送带上的一段物品流（同一种 itemId 的连续填充段），含：
- `fillCount`：填充计数（已填充到的格子位置）
- `drainCount`：排空计数（已排空到的格子位置）
- `freezeProgress`：冻结的动画进度

`syncLegacyFromSegments()` 将 `itemSegments` 同步回 legacy 字段（itemId/itemFillCount 等），并清理、排序、合并相邻同物品段。

### 8.3.3 物流桥不拆分传送带

传送带**不再拆分**，保持完整路径穿过物流桥格子，物品直接通过。这简化了状态管理，避免了拆分/合并的复杂性。

### 8.3.4 转角不能放置物流桥

物流桥不能创建在转角传送带格子上。`_isBeltCellTurn` 判定转角格：
- 单格传送带：用 incoming vs forced
- 首格：用 incoming vs 出方向
- 末格：不算转角
- 中间格：入方向 ≠ 出方向

`_isPathValidAtBeltCrossings` 返回 false for 转角格（预览变红），`_autoCreateBridgesAtCrossings` 跳过转角格，`_computePreviewBridgeCells` 隐藏转角格的桥预览。

### 8.3.5 物品状态继承

当传送带被加长/截断/分叉/合并时，新传送带需要继承旧传送带的物品状态（itemId、fill/drain progress、time anchors、residual items）：

| 场景 | 继承方法 |
|------|----------|
| 加长断头（committedSourceBelt） | 直接继承 itemSegments |
| 从终点延伸（sourceBelt） | 直接继承 itemSegments |
| 分叉（forkSourceBelt） | 用 `clippedItemSegments` 裁剪 |
| 合并（_mergeTarget） | 用 `shiftedItemSegments` 偏移 newSegmentLength-1 |
| 下游合并 | 继承下游物品 |

### 8.3.6 渲染分层

`_renderWithSvg` 两趟绘制：
1. **第一趟**：画背景（传送带本体），可被相邻背景覆盖
2. **第二趟**：画前景（指针/物品），优先级 物品 > 残留物品 > 指针

支持 `hiddenBackgroundCells` 半透明绘制、`hideTerminalBackground` 跳过末格背景。
