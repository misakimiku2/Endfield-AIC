# 物流桥重构修改总结

## 概述

本次修改解决了物流桥的两个核心问题：
1. 物流桥渲染从矩形替换为 SVG 素材
2. 重构传送带创建逻辑，使传送带可穿过物流桥，并在交叉时自动创建物流桥

## 修改文件清单

| 文件 | 修改内容 |
|------|----------|
| `assets/svg/Belt_Bridge.svg` | 简化 SVG，移除 Inkscape pattern 填充和 path-effect，确保 flutter_svg 兼容 |
| `lib/AIC/Logistics Units/transport_belt.dart` | 传送带穿过物流桥、自动创建物流桥、方向约束强化、修复并发修改 bug |
| `lib/canvas/canvas_editor.dart` | 传递 `getBuilding` 回调给 TransportBeltController |

---

## 一、SVG 渲染修复

**问题**：原 `Belt_Bridge.svg` 使用了 Inkscape 特有的 `<pattern>` 填充（斜线条纹）和 `inkscape:path-effect`（圆角效果），flutter_svg 无法正确渲染，导致物流桥回退显示为矩形。

**解决方案**：
- 移除所有 Inkscape 命名空间（`inkscape:`、`sodipodi:`）
- 移除 `<pattern>` 定义和 `fill:url(#pattern28)` 引用，替换为纯色 `fill:#b0b0b0`
- 移除 `inkscape:path-effect` 引用，保留圆角后的路径数据（`d` 属性已包含圆角效果）
- 简化后的 SVG 包含 3 个核心元素：深色底板 rect(#212121)、浅色面板 rect(#cecccc)、两个桥形通道 path

**相关文件**：`logistics_unit_renderer.dart` 已有 SVG 加载和渲染逻辑，物流桥映射到 `Belt_Bridge.svg`，无需额外修改。

## 二、传送带穿过物流桥

**问题**：原逻辑中 `_isCellOccupied()` 和 `_getOccupiedCellSet()` 将物流桥格子视为已占用，寻路无法通过物流桥。

**修改内容**：

### 2.1 `_isCellOccupied()` — 跳过物流桥格子
物流桥格子不视为已占用，传送带寻路可穿过。

### 2.2 `_getOccupiedCellSet()` — 排除物流桥格子
物流桥格子不加入阻挡集合。

### 2.3 `_hasIndependentBeltCell()` — 物流桥格子视为独立格子
传送带路径经过物流桥时，物流桥格子算作独立格子，不触发"设备间无传送带"检查。

### 2.4 `_handleFirstAnchor()` — 允许从物流桥格子开始创建
点击物流桥格子时，允许从该格开始创建传送带，不施加方向约束。

### 2.5 `_handleSubsequentAnchor()` — 物流桥格子不视为已占用
后续锚点处理时，物流桥格子允许作为传送带路径的一部分。

### 2.6 `_finish()` — 在物流桥处拆分传送带
传送带路径包含物流桥格子时，在物流桥处将传送带拆分为多段。物流桥格子同时属于前后两段传送带（作为前段的末格和后段的首格）。

新增辅助方法：
- `_findBeltBridgeAtCell(Offset)` — 查找指定格子上的物流桥建筑
- `_splitBeltAtBridges(ConveyorBelt)` — 在物流桥处拆分传送带，返回拆分后的列表
- `_createBeltSegment(source, path, startIdx, endIdx)` — 创建拆分后的传送带段

## 三、自动创建物流桥

**问题**：原代码没有自动创建物流桥的逻辑。当创建一条传送带穿过另一条传送带时，需要手动放置物流桥。

**修改内容**：

### 3.1 交叉检测
新增方法：
- `_isPerpendicularCrossing(dir1, dir2)` — 判断两个方向是否垂直交叉（一个水平一个垂直）
- `_getBeltDirectionAtCell(belt, cellIndex)` — 获取传送带在指定格子处的移动方向
- `_getPathDirectionAtIndex(path, index)` — 获取路径在指定索引处的移动方向

### 3.2 `_autoCreateBridgesAtCrossings()` — 自动创建物流桥
在 `_finish()` 中调用，检测 fullPath 与已有传送带的垂直交叉：
1. 收集所有交叉点（新传送带与已有传送带在相同格子处方向垂直交叉）
2. 先放置所有物流桥建筑（通过 `getBuilding` 回调获取 Building 定义）
3. 按被交叉传送带分组，对每条传送带一次性拆分（避免并发修改问题）
4. 拆分逻辑复用 `_createBeltSegment` 方法

### 3.3 `getBuilding` 回调
`TransportBeltController` 构造函数新增可选参数：
```dart
final Building? Function(String buildingId)? getBuilding;
```

`canvas_editor.dart` 在实例化时传入：
```dart
getBuilding: widget.dataLoader.getBuilding,
```

## 四、方向约束强化

**问题**：传送带经过物流桥时可能转弯，违反"物流桥里的传送带不能转弯"的规则。

**修改内容**：

### 4.1 BFS 寻路方向约束
`_BFSNode` 增加 `incomingDir` 字段（0=up, 1=right, 2=down, 3=left, -1=起点无方向）。

`_findPathBFS()` 修改：
- 当节点位于物流桥格子且 `incomingDir >= 0` 时，只允许沿入方向扩展（直线通过）
- 当节点不在物流桥格子上时，正常四方向扩展
- visited key 在物流桥格子处包含方向信息（`${nx}_${ny}_$dirIdx`），允许不同方向到达同一格子

### 4.2 Momentum Path 验证
新增 `_isPathValidAtBridges(path)` 方法：
- 遍历路径中每个物流桥格子
- 检查前后方向是否一致（入方向 = 出方向）
- 如果在物流桥处转弯，返回 false

`_findPath()` 修改：
- momentum path 生成后调用 `_isPathValidAtBridges` 验证
- 验证不通过则回退到 BFS 寻路

## 五、修复 `_autoCreateBridgesAtCrossings` 并发修改 bug

**问题**：原实现逐个处理交叉点，处理第一个交叉点后传送带被移除，后续交叉点引用的索引失效。

**解决方案**：
1. 先放置所有物流桥建筑（不拆分传送带）
2. 按被交叉传送带分组
3. 对每条传送带，使用 `_findBeltBridgeAtCell` 查找所有物流桥格子索引，一次性拆分
4. 拆分逻辑复用 `_createBeltSegment` 方法，保持一致性

## 物流桥工作原理

物流桥是传送带的十字路口，功能是让两条传送带交叉运输互不干扰：
- 四个边既是输出端也是输入端
- 传送带可穿过物流桥进行创建
- 创建传送带遇到交叉（垂直传送带穿过水平传送带）时，自动创建物流桥
- 物流桥里的传送带不能转弯：垂直传送带物品只能传输到垂直传送带，横向也是如此

物品传输使用方向通道（lane）机制：
- `outputItems` Map 的 key 格式为 `__bridge_lane__{direction}__{itemId}`
- 物品从某方向进入，只能从相同方向输出
- `_beltArrivalDirection()` 确定传送带到达方向
- `_beltExitDirection()` 确定传送带离开方向
