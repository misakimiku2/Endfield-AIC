## 10.2 ProjectState 共享中枢

`ProjectState` 是 `CanvasEditor` 与 `SimulationEngine` 共同持有的同一个引用，是项目的状态中枢。

### 写入方与字段分工

| 写入方 | 写入字段 | 触发刷新方式 |
|--------|----------|--------------|
| `CanvasEditor`（交互） | `buildings`、`conveyors` 列表增删；`PlacedBuilding.gridX/Y/rotation`；`ConveyorBelt.itemSegments/itemFillCount/lastItemId` | `widget.onProjectChanged` + `setState` |
| `CanvasEditor`（动画） | `ConveyorBelt.flowProgress`（视觉）；`PlacedBuilding.inputItemCount/outputItems`（即时交互） | `setState` |
| `SimulationEngine`（tick） | `PlacedBuilding.productionProgress/outputItems/isBlocked/inputItemId/inputItemCount/activeRecipeId`；`ConveyorBelt.flowProgress/isBlocked` | `notifyListeners()` |

### 重要约束

`SimulationEngine._applyTickResult` 在传送带有 `itemSegments` 时**仅更新** `flowProgress` 和 `isBlocked`，**不覆盖** `itemSegments/itemFillCount/lastItemId`，避免与 `CanvasEditor` 的传送带物品动画冲突。

## 10.3 模块间数据流

### 流 A：用户交互流

```
用户输入（鼠标/键盘/滚轮）
   → Listener / GestureDetector / Focus 回调
   → 修改 _targetScale/Offset/Angle 或 _placingRotation/_movingBuilding
   → _ticker lerp 平滑 _display* → setState
   → _EditorPainter.paint 重绘
   → 若涉及数据变更（放置/删除/移动/传送带）
        → widget.onProjectChanged(_project)
```

### 流 B：传送带物品动画流（CanvasEditor 内部）

```
_beltArrowController (2s 循环 AnimationController) addListener
   → _onBeltAnimationFrame(globalProgress)
   → 对每条传送带 belt.animationProgress(globalProgress) 跨零检测
   → _tickSingleBeltOnce:
        源设备输出 → belt.pushSourceItem → _consumeOutputItemForBeltStart
        belt.advanceItemSegments
        终点 → _transferBeltOutputToBuilding（含自动选配方/仓库入库）
   → 库存变化 → widget.onProjectChanged + setState
```

> **设计要点**：这条流由 `AnimationController` 驱动，负责传送带物品的**逐格视觉推进**与建筑库存的**即时交互**。它独立于 `SimulationEngine`，避免动画帧率与仿真 tick 解耦。

### 流 C：仿真引擎流（Isolate 模式）

```
主线程:
  attach(project) → _syncState()
     → _syncRevision++
     → ProjectState → SimSyncState.toJson
     → _workerSendPort.send({'type':'sync','data':...})

  start() → _sendControl('start')

Isolate (sim_worker):
  _onMessage('sync') → SimSyncState.fromJson → 替换本地副本
  _onMessage('start') → _tickTimer 启动 20Hz
  _onTick:
     dt = _speedMultiplier / 20
     _updateConveyors(dt)  // flowProgress += dt*60, isBlocked 判定
     _updateBuildings(dt)  // 自动选配方 → 消耗输入 → progress += dt/processTime → 产出
     构造 SimTickResult (含 revision)
     _mainSendPort.send(result.toJson())

主线程:
  _onMessageFromWorker(Map)
     → SimTickResult.fromJson
     → 校验 result.revision == _syncRevision（过期丢弃）
     → _applyTickResult: 写回 pb.isBlocked/productionProgress/input*/outputItems,
                        belt.flowProgress/isBlocked
     → notifyListeners() → CanvasEditor 重绘
```

### 流 D：Web 回退流（SimulationEngine，无 Isolate）

```
start() → _fallbackTimer 20Hz
_onFallbackTick:
   dt = _speedMultiplier / 20
   _fallbackUpdateConveyors(dt)  // 直接改 belt.flowProgress/isBlocked
   _fallbackUpdateBuildings(dt)  // 直接改 pb.productionProgress/outputItems
   notifyListeners()
```

## 10.4 渲染器分发

`_EditorPainter._renderBuildingStatic` 根据 `Building.id` 分发到各专用渲染器：

```
Building.id 判定
   │
   ├── RefiningUnitConfig.id ('refining_unit_3x3')
   │      → RefiningUnitRenderer.render + renderLogo
   │
   ├── DepotLoaderConfig.id / DepotUnloaderConfig.id
   │      → DepotAccessRenderer.render + renderLogo
   │
   ├── LogisticsUnitRenderer.isLogisticsUnit(id)
   │      → LogisticsUnitRenderer.render
   │
   └── 其他（默认）
          → BuildingRenderer.renderBuilding
```

传送带渲染独立调用 `TransportBeltRenderer.renderConveyorPath`。

## 10.7 关键协作点总结

1. **ProjectState 是共享中枢**：`CanvasEditor` 与 `SimulationEngine` 都持有同一个 `ProjectState` 引用。`CanvasEditor` 处理交互式写入（放置/移动/传送带物品推进），`SimulationEngine` 处理后台生产 tick 写入（progress/outputItems）。两者都通过 `notifyListeners` 或 `onProjectChanged` 触发 UI 刷新。

2. **revision 一致性**：`SimulationEngine._syncState` 每次自增 `_syncRevision` 并随同步包发送；worker 在结果中回传相同 revision；主线程只应用 `result.revision == _syncRevision` 的结果，保证过期数据不会覆盖最新状态。

3. **双 tick 机制并存**：
   - `CanvasEditor._onBeltAnimationFrame`：由 `AnimationController` 驱动，跨零触发，负责传送带物品的**逐格视觉推进**与建筑库存的**即时交互**。
   - `SimulationEngine`/`_SimWorker._onTick`：20Hz 定时器，负责建筑**配方生产进度**。
   两者通过 `ProjectState` 的字段分工，避免冲突。

4. **渲染缓存**：`_EditorPainter._pictureCache` 以 `buildingId_rotation_detailLevel_assetVersion_portsHash` 为 key 缓存 `ui.Picture`，避免每帧重绘建筑静态部分；端口状态变化（含预览蓝）会改变 portsHash 从而失效缓存。

5. **平台分支**：`SimulationEngine.init` 通过 `kIsWeb` 分支——原生平台用 Isolate 计算（不阻塞 UI），Web 平台用主线程定时器回退（逻辑镜像 worker）。

6. **渲染器与控制器解耦**：`TransportBeltController` 只产生 `ConveyorBelt` 数据，`TransportBeltRenderer` 负责绘制。两者通过数据模型解耦，便于独立测试与维护。

7. **弹窗统一分发**：`BuildingDetailDialog.show` 按 `building.id` 选择子面板，避免在 `EditorPage` 中硬编码类型判断。子面板通过回调（`onMove`/`onDelete`/`onInventoryChanged`/`onOutputItemSelected`）与外部通信。
