### TD-001: 缺乏 app 级统一状态管理方案 — ✅ 已完成

**处理方式（最小化范围）**：
- 引入 `provider` 依赖（`pubspec.yaml` 中本已存在），新增 `lib/state/project_notifier.dart`：
  `ProjectNotifier extends ChangeNotifier` 包裹现有可变 `ProjectState`，提供单一入口 `notifyChanged()`（内部 `_engine.attach()` + `notifyListeners()` + 版本自增）。
- `main.dart` 用 `MultiProvider` 注册 `DataLoader`、`SimulationEngine`、`ProjectNotifier` 三个 provider；`EditorPage` / `CanvasEditor` 不再透传 `dataLoader`/`simulationEngine`/`project` 构造参数。
- `CanvasEditor` 通过 `context.read<ProjectNotifier>()` / `context.watch<...>()` 访问状态；删除 11 处 `widget.onProjectChanged` 回调链，改调 `_pn.notifyChanged()`。
- `EditorPage` 删除 `_onSimTick` + `addListener`/`removeListener`（订阅交给 Provider）。
- 重绘模型：Isolate tick（`context.watch<SimulationEngine>()`）、传送带动画（CanvasEditor 自有 `_beltArrowController` + 局部 setState）、结构性变更（`context.watch<ProjectNotifier>()`）三者并存。

**保留项（标注为后续中等范围）**：`onBuildingPlaced`/`onBuildingSelected`/`onErrorToast` 三个 UI 协调回调与 `GlobalKey<CanvasEditorState>` 命令式方法暂未消除——彻底删除需引入 `EditorUiNotifier`，属"中等"范围，留待后续。

### TD-002: 数据模型与业务逻辑混杂 — ✅ 已完成

**探索结论（修正了文档原设想）**：`PlacedBuilding` 上的"业务方法"大多是改动自身字段的薄包装，真正的物流编排已在 `belt_simulation_logic.dart` 里；Isolate 完全独立（用 `SimBuildingData` DTO 重写逻辑，从不接触 `PlacedBuilding`）。文档原本设想的"抽到 Repository/Service"收益有限，故采用**最小有效范围**。

**处理方式**：拆分 `outputItems` 用字符串前缀（`__bridge_lane__`/`__splitter_slot__`）复用的 4 个逻辑缓冲区：
- 新增显式字段：`Map<String,String> bridgeLaneItems`、`String? splitterBufferedItemId`、`String? splitterBufferedDirection`
- 删除前缀魔法常量与私有方法（`_bridgeLanePrefix`/`_splitterSlotKey`/`_bridgeLanePrefixFor`/`_bridgeLaneKey`）
- 改写方法（签名不变）：`bridgeItemIdForOutputDirection`/`canAcceptBridgeInputItem`/`acceptBridgeInputItem`/`consumeBridgeOutputItem`/`splitterBufferOccupied`/`acceptIntoBuffer`/`consumeFromBuffer`
- 删除死字段 `convergerCycleIndex`（从未被读/写，汇流器已改用 `convergerArrivalTimestamps` 的 FCFS 机制）

**安全前提**：Isolate 在 `_applyTickResult`(simulation_engine.dart:104) 跳过所有物流设备，第 114 行的 `outputItems` 覆盖只作用于生产设备，故物流缓冲移到独立字段无冲突。改动集中在 `lib/models/project.dart` 一个文件。

### TD-004: JSON 解析缺乏类型安全封装 — ✅ 已完成

**处理方式**：新增 `lib/utils/json_parse.dart`，两个扩展方法：
- `JsonParse on Map<String, dynamic>`：`getDouble`（必填，缺失/类型不符抛 `FormatException`）、`getDoubleOrDefault`（可选，带默认值）、`getDoubleOrNull`（可能为 null）
- `OffsetParse on Map`：`getDouble` + `offset()`（从 `{'x','y'}` 节点直接读 `Offset`），用于 List 元素是动态类型的场景

替换全部 21 处 `(json[...] as num).toDouble()`，覆盖 3 类完全不同的 JSON 来源：静态游戏数据（`building.dart`/`recipe.dart`）、Isolate 通信协议（`sim_protocol.dart`/`sim_worker.dart`）、蓝图导入（`editor_page.dart`）。

## 待处理项（TD-008 ~ TD-010）

### TD-008: Isolate 处理逻辑复杂
**严重程度**: P2（中）

**问题描述**:
- Web 平台不支持 Isolate，需要单独处理
- `SimulationEngine`（`lib/canvas/simulation_engine.dart`）中原生 Isolate 逻辑与 Web 主线程回退逻辑混杂在同一类内（`_fallback*` 系列方法约 10 个与原生路径并存）
- 回退模式代码路径复杂，难以测试

**代码位置**:
```dart
// lib/canvas/simulation_engine.dart
Future<void> init() async {
  if (kIsWeb) {
    // Web 平台回退
    return;
  }
  try {
    _isolate = await Isolate.spawn(simWorkerEntry, _mainReceivePort!.sendPort);
  } catch (e) {
    debugPrint('[SimulationEngine] Isolate 初始化失败，回退到主线程模式: $e');
    // 失败后回退
  }
}
// 同一类内还有 _fallbackUpdateConveyors / _fallbackUpdateBuildings / _fallbackPushOutputToBelts 等回退实现
```

**建议解决方案**:
```dart
// 创建平台抽象接口
abstract class SimulationWorker {
  Future<void> init();
  Future<void> attach(ProjectState project);
  void start();
  void stop();
}

// 原生平台实现
class IsolateSimulationWorker implements SimulationWorker { ... }

// Web 平台实现
class MainThreadSimulationWorker implements SimulationWorker { ... }

// 工厂方法
SimulationWorker createWorker() {
  return kIsWeb
    ? MainThreadSimulationWorker()
    : IsolateSimulationWorker();
}
```

**预期收益**:
- 逻辑分离，更易测试
- 添加新平台更容易
- 降低主文件复杂度

**工作量估计**: 3 天

### TD-009: 缺乏统一错误处理机制
**严重程度**: P1（中高）

**问题描述**:
- 全项目实测约 24 处 `debugPrint`，仅开发环境可见，生产环境不可见
- 无错误分类和上报（项目中无 `ErrorSeverity`/`AppError` 之类的抽象）
- JSON 解析、资源加载失败时缺乏友好提示，仅打印日志

**当前做法**:
```dart
// lib/main.dart - SVG 预加载（真实代码）
Future<void> _precacheSvg(String path) async {
  try {
    await vg.loadPicture(SvgAssetLoader(path), null);
  } catch (e) {
    debugPrint('[precache] SVG 加载失败: $path -> $e');  // 仅开发环境可见
  }
}
```

**建议解决方案**:
```dart
// lib/utils/error_handler.dart
enum ErrorSeverity { info, warning, error, critical }

class AppError {
  final String message;
  final ErrorSeverity severity;
  final String? code;
  final StackTrace? stackTrace;

  void report() {
    // 统一上报逻辑
    debugPrint('[$severity] $code: $message');
    if (severity == ErrorSeverity.critical) {
      // 发送到崩溃服务
    }
  }
}

// 使用
try {
  await operation();
} catch (e, stackTrace) {
  AppError(
    message: 'SVG 加载失败',
    severity: ErrorSeverity.warning,
    code: 'SVG_LOAD_FAILED',
    stackTrace: stackTrace,
  ).report();
}
```

**预期收益**:
- 生产环境错误可见
- 便于问题追踪
- 用户体验更好

**工作量估计**: 2 天
