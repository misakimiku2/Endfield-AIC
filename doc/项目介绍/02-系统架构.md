# 02 — 系统架构

## 2.2 各层职责

### 数据层
- **`DataLoader`**：通过 `rootBundle` 读取 `assets/data/` 下的三个 JSON 文件，反序列化为 `Map<String, 模型>`，提供按 ID 查询、按 category 过滤、按建筑查配方等便捷方法。
- **JSON 数据库**：`buildings_db.json` / `items_db.json` / `recipes_db.json`，统一外层结构 `{ version, <主体 key>: { <id>: { ... } } }`。

### 模型层
- **元数据模型**（不可变）：`Building`、`Item`、`Recipe`，仅提供 `fromJson` 工厂构造，描述游戏静态数据。
- **运行时状态模型**（可变）：`ProjectState` 是整个项目的状态中枢，包含 `List<PlacedBuilding>`、`List<ConveyorBelt>`、视图变换、全局仓库库存。`PlacedBuilding` 与 `ConveyorBelt` 内部封装了物品缓存、生产进度、传送带物品段等复杂状态。

### 业务逻辑层
- **`SimulationEngine`**：仿真引擎，封装 Isolate 生命周期与状态同步，以 20Hz 推进生产 tick；Web 平台自动回退到主线程定时器。
- **`TransportBeltController`**：传送带创建控制器，处理点击/悬停/快捷键，BFS + 动量路径寻路，自动检测交叉并放置物流桥，合并/截断/分叉旧传送带并继承物品状态。
- **各设备渲染器**：`RefiningUnitRenderer`、`DepotAccessRenderer`、`LogisticsUnitRenderer`、`TransportBeltRenderer`，负责将设备绘制到 Canvas。

### UI 展示层
- **`EditorPage`**：应用主页面，承载工具栏、画布、设备栏、状态栏。
- **`CanvasEditor`**：画布 StatefulWidget，处理所有用户交互（缩放/平移/旋转/放置/移动/长按/传送带创建），通过 `_EditorPainter` 完成全部渲染。
- **弹窗与面板**：`BuildingDetailDialog`（统一入口，按 building.id 分发到子面板）、`ConveyorBeltDialog`、`DefaultSynthesisPanel`、`DepotLoaderPanel`/`DepotUnloaderPanel`、`LogisticsBridgePanel`。

## 2.3 运行时数据流

项目存在**两套并行的 tick 机制**，通过 `ProjectState` 的不同字段分工：

### 流 A：用户交互流（CanvasEditor）

```
用户输入（鼠标/键盘/滚轮）
   → Listener / GestureDetector / Focus 回调
   → 修改 _targetScale/Offset/Angle 或 _placingRotation/_movingBuilding
   → _ticker lerp 平滑 _display* → setState
   → _EditorPainter.paint 重绘
   → 若涉及数据变更（放置/删除/移动/传送带）
        → widget.onProjectChanged(_project)
```

### 流 B：传送带物品动画流（CanvasEditor 内部，独立于 SimulationEngine）

```
_beltArrowController (2s 循环 AnimationController) addListener
   → _onBeltAnimationFrame(globalProgress)
   → 对每条传送带 belt.animationProgress(globalProgress) 跨零检测
   → _tickSingleBeltOnce:
        源设备输出 → belt.pushSourceItem → _consumeOutputItemForBeltStart
        belt.advanceItemSegments
        终点 → _transferBeltOutputToBuilding（含自动选配方/仓库入库）
   → 库存变化 → widget.onProjectChanged + setState
```

> **设计要点**：这条流由 `AnimationController` 驱动，负责传送带物品的**逐格视觉推进**与建筑库存的**即时交互**（源消耗、终点入库）。它独立于 `SimulationEngine`，避免动画帧率与仿真 tick 解耦。

### 流 C：仿真引擎流（SimulationEngine，Isolate 模式）

```
主线程:
  attach(project) → _syncState()
     → _syncRevision++
     → ProjectState → SimSyncState.toJson
     → _workerSendPort.send({'type':'sync','data':...})

  start() → _sendControl('start')

Isolate (sim_worker):
  _onMessage('sync') → SimSyncState.fromJson → 替换本地副本
  _onMessage('start') → _tickTimer 启动 20Hz
  _onTick:
     dt = _speedMultiplier / 20
     _updateConveyors(dt)  // flowProgress += dt*60, isBlocked 判定
     _updateBuildings(dt)  // 自动选配方 → 消耗输入 → progress += dt/processTime → 产出
     构造 SimTickResult (含 revision)
     _mainSendPort.send(result.toJson())

主线程:
  _onMessageFromWorker(Map)
     → SimTickResult.fromJson
     → 校验 result.revision == _syncRevision（过期丢弃）
     → _applyTickResult: 写回 pb.isBlocked/productionProgress/input*/outputItems,
                        belt.flowProgress/isBlocked
     → notifyListeners() → CanvasEditor 重绘
```

### 流 D：Web 回退流（SimulationEngine，无 Isolate）

```
start() → _fallbackTimer 20Hz
_onFallbackTick:
   dt = _speedMultiplier / 20
   _fallbackUpdateConveyors(dt)  // 直接改 belt.flowProgress/isBlocked
   _fallbackUpdateBuildings(dt)  // 直接改 pb.productionProgress/outputItems
   notifyListeners()
```

## 2.4 共享数据中枢：ProjectState

`ProjectState` 是 `CanvasEditor` 与 `SimulationEngine` 共同持有的同一个引用：

| 写入方 | 写入字段 | 触发刷新方式 |
|--------|----------|--------------|
| `CanvasEditor`（交互） | `buildings`、`conveyors` 列表增删；`PlacedBuilding.gridX/Y/rotation`；`ConveyorBelt.itemSegments/itemFillCount/lastItemId` | `widget.onProjectChanged` + `setState` |
| `CanvasEditor`（动画） | `ConveyorBelt.flowProgress`（视觉）；`PlacedBuilding.inputItemCount/outputItems`（即时交互） | `setState` |
| `SimulationEngine`（tick） | `PlacedBuilding.productionProgress/outputItems/isBlocked/inputItemId/inputItemCount/activeRecipeId`；`ConveyorBelt.flowProgress/isBlocked` | `notifyListeners()` |

> **重要约束**：`SimulationEngine._applyTickResult` 在传送带有 `itemSegments` 时仅更新 `flowProgress` 和 `isBlocked`，**不覆盖** `itemSegments/itemFillCount/lastItemId`，避免与流 B 的传送带物品动画冲突。

## 2.5 revision 一致性机制

`SimulationEngine._syncState` 每次自增 `_syncRevision` 并随同步包发送；worker 在结果中回传相同 revision；主线程只应用 `result.revision == _syncRevision` 的结果，保证过期数据不会覆盖最新状态。

```
主线程 _syncRevision = 5 → 发送 sync(rev=5)
用户放置新建筑 → _syncRevision = 6 → 发送 sync(rev=6)
worker 仍在处理 rev=5 → 回传 result(rev=5)
主线程收到 result(rev=5) → 5 ≠ 6 → 丢弃
worker 收到 sync(rev=6) → 替换副本
worker 回传 result(rev=6) → 主线程应用
```

## 2.6 渲染缓存策略

`_EditorPainter._pictureCache` 以 `buildingId_rotation_detailLevel_assetVersion_portsHash` 为 key 缓存 `ui.Picture`，避免每帧重绘建筑静态部分。端口状态变化（含预览蓝色）会改变 `portsHash` 从而失效缓存。`_forceRepaint` 在资源加载完成时清空缓存强制刷新。

## 2.7 平台分支

`SimulationEngine.init` 通过 `kIsWeb` 分支：

- **原生平台**：`Isolate.spawn(simWorkerEntry, ...)` 启动独立 Isolate 计算，主线程不阻塞。
- **Web 平台**：直接返回，使用 `_fallbackTimer` + 镜像逻辑的方法组在主线程运行。

两套路径共享相同的 `dt = _speedMultiplier / _tickRate` 公式与生产逻辑。
